## 1. 项目背景与路线决策

- **起点**：原项目是 ROS 生态的机械臂上位机/下位机（`dummy_moveit_ws_restructured`、`dummy-ref-core-fw`）。下位机固件中有 `6dof_kinematic.cpp`，定义了 DH 参数、FK、解析 IK。
- **现状**：已有一个 WPF C# 上位机工程 `DummyWpfUpper`（.NET 8，net8.0-windows）。
- **关键决策**：用户明确表示「我在学习上位机的时候，想要 C# 实现」，因此**放弃 rosbridge / ROS2 依赖路线**，改为**纯 C# 自研**：运动学、规划、伺服、仿真、协议层全部在 C# 侧实现。
- **用户逐项点选实现的能力**（按顺序）：
  1. `1` → C# 侧 IK/FK
  2. `2` → 内置仿真器
  3. `3` → RRT 路径规划与自动避障
  4. `笛卡尔 servo` → 笛卡尔速度伺服（已完成，含 CLI 验证）

**尚未点选的后续候选**（用户曾问及但没要求实现）：
- 手爪 ASCII 接口
- fibre 二进制协议客户端
- 硬件急停状态反馈/电气安全方案（软件不能替代安全回路）

## 3. 核心约定（务必遵守）

1. **单位**：
   - 底层移植的 `SolveFk()` 输出 **米/弧度**，`SolveIk()` 输入 **毫米/度**。
   - 高层 API 统一 **mm / deg**：`SolveFkMm()`、`SolveIkBest()`、`ComputeJacobian()`、`GetLinkPoints()`（后者返回米，供碰撞检测）。
   - `CartesianServo` 的 twist：线速度 **mm/s**，角速度 **deg/s**；关节速度 **deg/s**。
2. **DH 参数**：`CreateDefault() = (0.109, 0.035, 0.146, 0.115, 0.052, 0.072)`（米）。
3. **关节限位**（测试/规划用）：
   - min = `{ -170, -73, 35, -180, -120, -720 }`
   - max = `{ 170, 90, 180, 180, 120, 720 }`
4. **Rest/仿真姿态**：`{ 0, -73, 180, 0, 0, 0 }` —— 这是**奇异位形**，IK 8 组解全超限位，测试要用非奇异姿态。
5. **推荐测试姿态**：`{ 30, -50, 90, 20, -30, 45 }`（IK 回环误差 0.0000 mm）。
6. **IK 选解策略**：仿固件 `MoveL()`，过滤限位后取与当前关节角「最大单轴差」最小的解（`SolveIkBest()`）。
7. **编译坑**：`DummyCli` 是 `DummyWpfUpper` 的子目录，主工程必须保留 `<Compile Remove="DummyCli/**" />`，否则重复 AssemblyAttributes 编译失败。

## 4. 关键实现细节

### 4.1 `Dof6Kinematics.cs`
- 完整移植下位机 `6dof_kinematic.cpp`：DH 表、FK、8 组解析 IK、欧拉↔旋转矩阵。
- 高层 API：
  - `Pose6D SolveFkMm(double[] jointsDeg)`
  - `Joint6D? SolveIkBest(Pose6D poseMm, double[] currentDeg, double[]? min, double[]? max)`
  - `double[,] ComputeJacobian(double[] jointsDeg)` —— 数值雅可比：位置行单位 mm/deg，姿态行 deg/deg。
  - `double[][] GetLinkPoints(double[] jointsDeg)` —— 返回 5 个点（米）：基座、J1、J2、J3、末端。曾为 6 点因 p4=p3 导致碰撞误判。
- 早期 bug：多余数组拷贝与共享 `_workR06` 字段 → 改为局部 `R06`。

### 4.2 统一后端 `IRobotBackend.cs`
- 真机 `RobotController` 与仿真 `SimulationController` 都实现它；UI、3D 视图、规划器、Servo 都只依赖接口。
- 包含 Connect/Disconnect、StartPolling、Home/Reset、MoveJ/MoveL、SetMotorDce/RebootMotor、坐标转换等。
- `MainViewModel` 中用固定委托字段 `_backendLogHandler` / `_backendStateHandler` 订阅，避免 lambda 退订失败。

### 4.3 仿真 `SimulationController.cs`
- 20Hz 刷新，`_currentJoints → _targetJoints` 按最大关节速度推进，更新 State/速度/FK 位姿。
- `MoveL()` 调 C# IK 后执行 `MoveJ()`（曾因 `double?` 接收 `int?` 编译失败，已修）。
- `ToggleSimulation()` 切换真机/仿真时会重建 Servo 实例。

### 4.4 碰撞检测 `TrajectoryPlanner.CheckCollisionFwDeg(double[] jointsFwDeg)`
- **重要**：原 `CheckCollision()` 用 URDF 坐标链，与实际下位机 FK 坐标不一致导致大量误报，已废弃；现统一用 `CheckCollisionFwDeg()`，基于 `Dof6Kinematics.GetLinkPoints()`。
- 自碰撞检测跳过零长度连杆与共享端点的相邻段。

### 4.5 `RrtPlanner.cs`
- 双向 RRT-Connect，6 维关节空间，`maxIterations=4000, stepDeg=12, goalBias=0.15`。
- `IsValid` 回调 = 限位 + `CheckCollisionFwDeg()`；`Smooth()` 贪心 shortcut。
- 返回 `RrtResult(List<double[]> Path, int Iterations, bool Success, string Message)`。

### 4.6 `CartesianServo.cs` —— 最新修复点
- `Compute(jointsDeg, twist, frame)`：tool 系 twist 先用 FK 的 `R` 旋到 base，再算 `dq`。
- **已修 bug（本次会话）**：`DampedLeastSquares` 原来构造 `JᵀJ` 却套任务空间公式 `Jᵀ(JJᵀ+λ²I)⁻¹v`，实际算出 `Jᵀ(JᵀJ)⁻¹v`，关节速度放大约 100 倍。现改为**关节空间形式**：
  ```
  dq = (JᵀJ + λ²I)⁻¹ Jᵀ v
  ```
  矩阵构造与 `SolveLinearSystem()`（高斯-约当带部分主元）配套。
- 阻尼默认 `0.05`（`Math.Max(0.001, damping)`）。

### 4.7 `ServoController.cs`
- 默认 33ms（约 30Hz）循环；每周期 `Compute` → 积分得到下一关节角 → 限位检查 → `CheckCollisionFwDeg` → `backend.MoveJ(next, null)`。
- 失败即 break 并写日志；`Start/Stop/UpdateTwist` 管理生命周期。

### 4.8 `MainViewModel.cs` 与 UI
- 已集成：JSON 持久化、日志导出、自动重连、关节速度显示、命名姿态、电机 DCE PID/REBOOT、后端切换、C# IK 的 `SendPoseArray()`、RRT 规划/播放、Servo 面板。
- `MainWindow.xaml` 行布局：状态区 Row4、日志区 Row5；示教区命名姿态 Row5；Servo 面板 Row3。
- `Robot3DWindow` 构造函数改为接收 `IRobotBackend`。

### 4.9 CLI `DummyCli/Program.cs`
- 命令：`start/stop/home/reset/disable/calibration/cmdmode/getjpos/getlpos/sendj/sendl/dce-*/reboot` + 三个离线验证命令。
- `iktest [j1..j6]`：FK→IK→FK 回环。
- `rrttest [start6 goal6]`：无参数时自动选安全起点/终点。
- `servotest [j1..j6 vx vy vz wx wy wz [base|tool]]`：默认姿态/默认 twist；用 `dt=1ms` 的 FK 有限差分反推末端速度验证，容差 0.5 mm/s 与 0.5 deg/s；tool 系用 `Rᵀ` 转回工具系比较。

## 5. 已修复 Bug 清单（历史）

1. 3D 相机 `_lookAt - direction * _distance` 是 `Vector3D`，不能赋给 `Point3D` → 逐分量构造。
2. 嵌套 `DummyCli` 导致重复 AssemblyAttributes → 主 csproj 加 `<Compile Remove="DummyCli/**" />`。
3. Home 奇异姿态 IK 失败 → 换非奇异测试姿态。
4. IK 多余拷贝与共享 `_workR06` → 局部化。
5. CLI IK 选解按回环误差导致选 180° 解 → 改用 `SolveIkBest()`。
6. `SimulationController.MoveL()` 类型 `double?` → `int?`。
7. 后端事件 lambda 退订失败 → 固定委托字段。
8. RRT 初始化捕获未赋值的 `_controller` → 移到硬件赋值后。
9. `rrttest` 调用不存在的 `FirmwareDegToRosRad()` → 改用 `CheckCollisionFwDeg()`。
10. 碰撞检测坐标系不一致 → 新增 `CheckCollisionFwDeg()`。
11. L3/L5 零长度段误判 → `GetLinkPoints()` 返回 5 点 + 跳过相邻/零长段。
12. XAML Grid.Row 重叠（RRT 与命名姿态同 Row4）→ 增加行，命名姿态移 Row5。
13. Servo 面板插入后状态区 Row3→Row4、日志区 Row4→Row5。
14. **DLS 伪逆公式错误（最新）** → 改关节空间 `(JᵀJ+λ²I)⁻¹Jᵀv`。

## 8. 本次会话新增（2026-11-23 下半天）

### 8.1 3D 视图连杆"散架"修复
- 用户截图显示机械臂连杆断裂/错位。根因：`Robot3DWindow.BuildScene()` 中 `Transform3DGroup`  children 顺序为 `[Translate, Rotate]`，WPF 按添加顺序应用，导致关节原点被一起旋转（变成 `R·(p+J)`）。
- 修复：改为先 `Rotate` 再 `Translate`（URDF 语义 `T(J)·R`，矩阵链 `R·T`），连杆恢复连贯。

### 8.2 3D 视图路径可视化（运动规划功能扩展）
- 新增 `Services/IRobotPathProvider.cs`：解耦 3D 视图与 ViewModel 的路径数据源，暴露 `PlannedPath` / `TaughtPath` + `PathsChanged` 事件。
- `MainViewModel` 实现该接口：示教点增删清空、RRT 规划成功/失败、配置加载后触发 `PathsChanged`。
- `Robot3DWindow` 改造：
  - 构造函数新增可选 `IRobotPathProvider` 参数（`MainWindow.Open3DView_Click` 传入 Vm）。
  - `ComputeToolPoint()` 用与场景树一致的 URDF 链（`frame = R·T·frame`，i=0..5，`frame.Transform(ToolOffset)`）算末端点，轨迹与模型严格对齐。
  - 规划路径画橙色细管 + 八面体点，示教路径画青色，起点绿/终点红。
  - 面板：显示路径复选框、轨迹预览按钮（80ms/点播放关节角，预览时暂停状态轮询更新，停止后恢复）。
- 验证：主工程/CLI 构建 0 警告 0 错误；`rrttest`、`iktest` 回归通过。

### 8.3 "切换仿真没反应"修复
- 用户点击切换仿真后状态区全 `--`、显示未连接。根因：`ToggleSimulation()` 只切换 `_controller`，未连接也未启动轮询；用户误以为无反应又点一次切回真机。
- 修复：切换到仿真时自动 `Connect("sim")` + `StartPolling()` + 设 `_manualDisconnect=false`，立即显示仿真姿态；切回真机时提示手动选端口连接；末尾调用 `UpdateConnectionState()` 刷新状态栏。
- 自动重连循环已有 `UseSimulation` 守卫，无冲突。
