## 第一部分：C# 语言基础（高频必背）

### 1. 值类型与引用类型的区别？装箱与拆箱是什么？

**标准答法：**
- **值类型**（struct、enum、基本数值类型）：存储在栈上，直接存储数据，赋值时拷贝值，互不影响。
- **引用类型**（class、string、数组、委托、接口）：存储在托管堆上，栈上只存引用地址，赋值时拷贝引用，多个变量指向同一对象。
- **装箱**：值类型转 object/接口类型时，在堆上分配对象并拷贝值，性能开销大。
- **拆箱**：object 转回值类型，需显式强转，可能抛 `InvalidCastException`。
- 注意：`string` 是引用类型但具有**值语义**（不可变性，内容相等比较）。

**加分点：** 面试官常追问——"在泛型出现前，`ArrayList.Add(int)` 每次都会装箱；泛型 `List<T>` 避免了装箱，所以性能更好。" 用 `is`/`as` 拆箱更安全；用 `boxing`/`unboxing` 尽量少的写法优化热点代码。

### 2. C# 中 `string` 和 `StringBuilder` 的区别？

**标准答法：**
- `string` 不可变，每次拼接（`+`）都会生成新对象，大量拼接产生大量垃圾、性能差。
- `StringBuilder` 可变，内部用字符缓冲区，拼接时只在容量不足时扩容，性能好。
- 适用场景：循环拼接、拼接次数多时用 `StringBuilder`；少量、一次性拼接直接用 `+` 或 `$` 插值即可。

**加分点：** `StringBuilder` 默认容量 16，可预估后初始化容量避免扩容。`string` 拼接编译器优化：常量拼接编译期已合并；运行时 `+` 对少量字符串可能优化为一次 `Concat`。

### 3. 简述 C# 的委托（delegate）与事件（event）？

**标准答法：**
- **委托**：类型安全的函数指针，封装了方法的引用，可多播（`+=` 链式调用多个方法）。是 C# 实现回调、观察者模式的基石。
- **事件**：委托的特化封装，对外只暴露 `+=`/`-=`，不能像委托那样在类外直接赋值或 Invoke，起到**封装与安全**作用。
- 事件本质是一个受保护的委托字段，由 `add`/`remove` 访问器实现。
- 典型：`Action`、`Func`、`EventHandler`、`EventHandler<TEventArgs>`。

**加分点：** 区分"事件与委托字段"——事件只能在声明它的类内部触发（`Invoke`），外部只能订阅/退订，这是防止外部破坏封装。多播委托的返回值只取最后一个方法。

### 4. 泛型是什么？为什么要用泛型？

**标准答法：**
- 泛型允许在定义类、方法、接口时暂不指定具体类型，用 `T` 占位，使用时再确定。
- 优点：**类型安全**（编译期检查）、**避免装箱拆箱**（对值类型性能优）、**代码复用**（一套逻辑服务多种类型）。
- 常用：`List<T>`、`Dictionary<K,V>`、`Nullable<T>`、泛型方法、泛型约束（`where T : class/struct/new()/接口/基类`）。

**加分点：** 泛型在 JIT 编译时对引用类型共享同一份代码、对值类型各自生成专门版本，因此值类型泛型性能好于 object 容器。

### 5. 什么是 LINQ？IEnumerable 与 IQueryable 的区别？

**标准答法：**
- LINQ（Language Integrated Query）：语言集成查询，用声明式语法操作集合，核心是**延迟执行**。
- `IEnumerable<T>`：在**内存中**执行，`Where`/`Select` 等返回迭代器，延迟到枚举时才执行（LINQ to Objects）。
- `IQueryable<T>`：面向**数据源**（EF、数据库），表达式树在真正枚举时翻译成 SQL 在数据库端执行。
- 关键点：`IQueryable` 的过滤条件会**下推到数据库**（减少数据传输），`IEnumerable` 则把数据全取回内存再过滤。

**加分点：** 面试常考"用 `IQueryable` 先 `Where` 再 `ToList()`"——`ToList()` 是立即执行，`Where` 是延迟执行，顺序影响 SQL 和性能。延迟执行陷阱：延迟变量在循环中被多次枚举会重复执行。

### 6. `ref`、`out`、`in` 关键字的作用？

**标准答法：**
- `ref`：按引用传递，**调用前必须初始化**，方法内可修改并影响外部。
- `out`：按引用传递，**调用前不必初始化**，方法内必须赋值后才能返回，常用于 TryGet 模式（`int.TryParse`）。
- `in`：只读引用传递，避免大结构体拷贝，方法内不可修改，用于性能优化。

**加分点：** 三者都传引用地址而非值。`in` 是 C# 7.2 引入，配合 `readonly struct` 可避免大结构体复制。

---

### 7. 什么是 async/await？与多线程的关系？

**标准答法：**
- `async/await` 是 C# 的异步编程模型，核心是**非阻塞等待**。
- `async` 方法返回 `Task`/`Task<T>`/`void`，`await` 挂起方法但不阻塞线程，I/O 完成后续继续执行（线程池回收线程）。
- 适合：I/O 密集（网络、数据库、文件）。CPU 密集应使用 `Task.Run` 或 `Parallel`。
- **不是多线程本身**：await 不创建新线程，异步是"协作式"的，真正干活的还是线程池线程，但调用线程不阻塞。

**加分点：** 常见坑——`async void` 只能在事件处理器用，异常无法捕获；`ConfigureAwait(false)` 在库代码中避免死锁；`await` 后默认回到原同步上下文（UI 线程），这是 WPF 中避免跨线程更新 UI 的关键机制（后面 WPF 部分会再讲）。

### 8. 什么是 GC？讲讲托管堆、代龄和 Dispose 模式？

**标准答法：**
- GC（垃圾回收）自动管理托管堆内存，标记不再可达的对象并回收，分为**第 0 代、1 代、2 代**（代龄越小回收越频繁）。
- 大对象堆（LOH，≥85KB）单独管理，不参与代龄压缩。
- 非托管资源（文件、数据库连接、Socket）需手动释放，实现 `IDisposable`，配合 `using` 语句自动调用 `Dispose`。

**加分点：** **Dispose 模式**：`using` 本质是 try/finally 里调用 `Dispose`；完整模式应同时实现 `IDisposable` 与终结器（析构函数），用 `GC.SuppressFinalize` 避免重复回收。终结点 `~Class()` 由 GC 调用，不可控，所以最好用 `using`/`Dispose` 主动释放。

### 9. 面向对象三大特性在 C# 中的体现？

**标准答法：**
- **封装**：类通过 `public/private/protected/internal` 访问修饰符隐藏内部实现，属性（get/set）提供受控访问。
- **继承**：子类继承父类成员，`override` 重写虚方法，`base` 调用基类；C# 单继承（类），多实现（接口）。
- **多态**：同一接口/基类引用，运行时调用不同实现——通过**虚方法重写**（`virtual/override`）和**接口**实现，依赖**运行时类型**决定调用版本（动态绑定）。

**加分点：** 区分 `abstract`（抽象类，可含实现，强制派生）与 `interface`（纯契约，C# 8 后可有默认实现）。`sealed` 阻止继承/重写。多态是 WPF/MVVM 里大量接口设计的基础。

### 10. `==` 与 `Equals` 的区别？`GetHashCode` 的作用？

**标准答法：**
- 值类型：`==` 与 `Equals` 都比较值（但 `==` 需类型相同才编译通过）。
- 引用类型：默认 `==` 比较引用地址；`Equals` 默认也比较引用，但可被重写为**按内容比较**（如 `string`）。
- `GetHashCode`：返回对象的哈希码，用于 `Dictionary`/`HashSet` 快速查找。
- **规则**：重写 `Equals` 必须重写 `GetHashCode`，保证相等的对象哈希码相同，否则哈希容器查找错乱。

**加分点：** `string` 重写了 `==` 使其按内容比较（这是 C# 的特殊设计，其他引用类型不这样）。引用类型间比较用 `ReferenceEquals`。

## 第二部分：C# 进阶 / .NET 框架（中频）

### 11. 反射（Reflection）是什么？优缺点？

**标准答法：**
- 反射在运行时动态获取类型信息（类型、属性、方法、特性）并创建对象、调用成员。
- 用途：插件系统、依赖注入、ORM 映射、序列化、特性（Attribute）解析。
- 缺点：**性能低**（比直接调用慢），破坏封装，异常在运行时才暴露。

**加分点：** 面试常考与特性（Attribute）结合——自定义 `[Attribute]` 需继承 `Attribute`，通过反射读取。性能敏感场景可用缓存 `PropertyInfo`/表达式树/`Emit` 替代频繁反射。

---

### 12. 依赖注入（DI）是什么？有哪些方式？

**标准答法：**
- 依赖注入是控制反转（IoC）的一种实现，由容器负责创建并注入对象的依赖，降低耦合、便于测试。
- 三种注入方式：**构造器注入**（最推荐，依赖明确）、**属性注入**、**方法注入**。
- .NET 内置 `Microsoft.Extensions.DependencyInjection`，支持三种生命周期：**Singleton**（全局单例）、**Scoped**（每次请求一个）、**Transient**（每次解析都新建）。

**加分点：** WPF 里可引入 DI 管理 ViewModel 与服务的生命周期。面试常问"Singleton 里注入 Scoped 会怎样"——会产生"生命周期提升/捕获"，Scoped 变成长寿对象，需避免。

---

### 13. 集合有哪些？各自特点？

**标准答法：**
- `List<T>`：动态数组，索引快，插入/删除中间元素慢。
- `Dictionary<K,V>`：哈希表，键值查找 O(1)，无序，键唯一。
- `HashSet<T>`：无序集合，去重，查找 O(1)。
- `Queue<T>`：先进先出（FIFO）。
- `Stack<T>`：后进先出（LIFO）。
- `LinkedList<T>`：双向链表，插入删除快，随机访问慢。
- `SortedDictionary`/`SortedSet`：基于红黑树，有序。

**加分点：** 面试会问"Dictionary 的底层"——数组 + 哈希冲突处理（链地址/开放寻址），扩容时重哈希；`GetHashCode` 的分布影响性能。

---

### 14. 锁与线程安全：lock、Monitor、Mutex、Semaphore 的区别？

**标准答法：**
- `lock`：语法糖，本质是 `Monitor.Enter/Exit`，同一进程内线程互斥，防止并发修改共享资源。
- `Monitor`：`lock` 的底层实现，提供 `TryEnter` 等更细控制。
- `Mutex`：可跨进程的互斥锁，用于进程间同步。
- `Semaphore`/`SemaphoreSlim`：信号量，允许 N 个线程同时访问（计数），适合限流/连接池。

**加分点：** C# 中线程安全集合 `ConcurrentDictionary`、`BlockingCollection`；`volatile` 保证可见性；`Interlocked` 提供原子操作。`lock` 内部是 `Monitor` + `try/finally` 保证异常时释放。

---

### 15. 什么是异常处理机制？自定义异常？

**标准答法：**
- C# 用 `try/catch/finally`，`finally` 无论是否异常都会执行，用于释放资源。
- 异常是从 `System.Exception` 派生的对象，按类型捕获（先派生后基类）。
- 自定义异常：继承 `Exception`，提供无参、带消息、带内部异常等构造函数。
- `throw` 抛出异常，`throw new` 抛新异常会**重置堆栈**，`throw;`（无参）保留原堆栈。

**加分点：** 面试常问"什么时候 catch"——捕获已知可处理异常，未知异常记录日志并抛出；不要用异常控制流程（性能差）。WPF 中可注册 `DispatcherUnhandledException` 全局兜底。

## 第三部分：MES 面试（行业核心）

### 16. 什么是 MES？它的核心价值是什么？

**标准答法：**
- MES（Manufacturing Execution System，制造执行系统）是**面向车间执行层**的信息化系统，位于 ERP 和现场自动化设备（PLC/SCADA）之间，负责生产现场的**计划执行、过程管控、数据采集与追溯**。
- 核心价值：解决"**黑箱生产**"问题——让管理层实时掌握车间真实生产状态，实现**透明化、可追溯、精益化**。
- 目标：提高设备利用率、降低不良率、缩短生产周期、实现批次/单件级追溯。

**加分点：** 用经典分层说——ERP（企业计划层）→ MES（制造执行层）→ PCS/SCADA（过程控制层）。MES 是"承上启下"的桥梁，MES 管"怎么产"，ERP 管"产什么、什么时候产"。

---

### 17. MES 和 ERP 的区别？

**标准答法：**
- **关注层级**：ERP 管计划、资源、财务（企业级）；MES 管车间执行、实时数据（车间级）。
- **数据粒度**：ERP 是订单/工单级、日/班次级；MES 是工序/工位/批次级、实时分钟级。
- **实时性**：ERP 偏计划与事后核算；MES 强调实时采集、实时反馈。
- **关系**：ERP 下计划给 MES，MES 回报实际产量、工时、质量给 ERP，形成闭环。

**加分点：** 一句话概括——"**ERP 告诉你要做什么（计划），MES 告诉你做得怎么样（执行）、正在做什么（实时）**。"

---

### 18. MES 的主要功能模块有哪些？

**标准答法：**（背熟 11 个核心模块）
1. **工单管理**（生产订单下发、拆分、排程）
2. **生产排程/计划**（APS，基于产能/交期排产）
3. **生产过程管理**（工序流转、报工、WIP 跟踪）
4. **物料管理**（物料批次、齐套、防错、追溯）
5. **质量管理**（IQC/PQC/OQC、SPC、不合格品处理、防呆）
6. **设备管理**（设备状态、OEE、点检、保养、维修）
7. **数据采集**（SCADA/PLC/扫码/手持终端采集）
8. **追溯管理**（正向/反向追溯，批次/序列号/条码）
9. **人员管理**（考勤、权限、上岗资质）
10. **报表看板**（实时产量、效率、良率、Andon）
11. **系统集成**（与 ERP、WMS、PLM、SCADA、设备接口）

**加分点：** 结合你的项目讲——如锂电池 MES 涉及**正负极配料、涂布、卷绕、装配、注液、化成、分容**等工序，重点讲**批次追溯、防错防呆、数据采集、质量管控**四个在锂电 MES 中最核心的能力。

### 19. 什么是追溯（Traceability）？如何实现？

**标准答法：**
- 追溯指通过条码/序列号/批次号，正向查到**产品用了哪些物料、经了哪些工序、谁操作、设备参数、质量结果**；反向从物料/批次查**用到哪些产品**。
- 实现要点：
  1. **唯一标识**：每批次/每件产品赋唯一条码（一物一码或批次码）。
  2. **关键数据绑定**：在工序采集点记录物料批次、操作员、设备、工艺参数、质量结果，与产品标识绑定。
  3. **数据链路完整**：从投料到出货全链路采集，缺一不可。
  4. **追溯查询**：按序列号/批次号快速反查整条链路。

**加分点：** 追溯粒度分**批次级**和**单件级**。锂电池多要求**电芯/模组/PACK 单件级追溯**，且工序间通过条码绑定形成追溯树（含电芯→模组→PACK 的母子关联）。这是 MES 面试最高频考点。

---

### 20. 什么是防错（防呆/Fool-proof）？MES 中如何实现？

**标准答法：**
- 防错（Poka-Yoke）指在生产过程中通过技术手段**防止错误发生或阻止错误流入下道工序**。
- MES 实现方式：
  - **扫码防错**：扫描物料/工单条码，系统校验是否正确、是否齐套、是否过站。
  - **工艺防错**：校验当前工序是否符合工艺路线，防止跳工序/漏工序。
  - **参数防错**：设备参数/配方与工单/产品绑定，超范围报警或锁机。
  - **物料防错（防混料）**：扫描核对物料批次是否匹配工单 BOM。
  - **Andon 停线**：异常触发报警/停线，防止不良继续生产。

**加分点：** 与"质量管控"绑定讲——"防错是 MES 把质量从**事后检验**变成**过程预防**的关键手段。"

---

### 21. 什么是 OEE？如何计算？

**标准答法：**
- OEE（Overall Equipment Effectiveness，设备综合效率），衡量设备真实效率的核心指标。
- **OEE = 时间开动率 × 性能开动率 × 合格品率**：
  - **时间开动率** = 实际运行时间 / 计划运行时间（反映停机损失）。
  - **性能开动率** = （理论节拍 × 产量）/ 实际运行时间（反映速度损失、小停机）。
  - **合格品率** = 合格品数 / 总生产数（反映质量损失）。
- 世界级标杆约 85%，一般企业 60%~80%。

**加分点：** 六大损失：故障、换型调整、空转小停、速度损失、不良返工、启动损失。MES 通过实时采集设备状态自动算 OEE，比手工统计更准确。

### 22. MES 与设备（PLC/SCADA）如何交互？采集哪些数据？

**标准答法：**
- 接口方式：**OPC UA**（现代主流，跨平台、安全）、Modbus/TCP、TCP/IP 报文、串口、数据库直读、MQTT。
- 采集数据：设备状态（运行/停机/报警）、产量计数、关键工艺参数（温度、压力、速度、电压电流）、报警记录、配方。
- 交互方向：MES 下发工单/配方/参数给设备；设备回传产量、质量、状态给 MES。
- SCADA 侧重**实时监控与数据采集**（过程级、毫秒级），MES 侧重**业务管理**（工单、追溯、质量），两者常配合使用。

**加分点：** OPC UA 是当前行业标准（信息模型 + 安全 + 平台无关）。锂电产线常见：涂布机、卷绕机、注液机等通过 OPC UA 与 MES 集成，采集关键参数用于追溯和 SPC。

### 23. 什么是 SPC？MES 中如何应用？

**标准答法：**
- SPC（Statistical Process Control，统计过程控制）用统计方法监控过程是否处于受控状态，识别异常波动。
- 核心工具：**控制图**（X-bar/R、X-bar/S 等）、CPK/PPK（过程能力指数）、正态分布。
- 判异准则：超出控制限、连续 7 点同侧、趋势性变化等。
- MES 应用：实时采集工艺参数，自动绘制控制图，**超限自动报警/停线**，实现质量预警。

**加分点：** CPK ≥ 1.33 一般认为过程能力充足；CPK 反映过程能力（相对规格），区别于 PPK（初期能力）。讲 SPC 时体现"用数据驱动质量，从被动检验到主动预防"。

## 第四部分：WPF 面试（核心高频）

### 26. 什么是 XAML？WPF 的架构分层？

**标准答法：**
- XAML（eXtensible Application Markup Language）是 WPF 的**声明式 UI 标记语言**，用 XML 语法描述界面结构，配合 Code-Behind（代码后置）实现 UI 与逻辑分离。
- WPF 架构分层：**托管层**（控件、布局、数据绑定）→ **媒体层**（图形、动画、文本、图像）→ **DirectX 层**（底层渲染，GPU 加速）。

**加分点：** WPF 是基于**保留模式渲染**（Retained Mode）的矢量 UI 框架，控件描述绘制逻辑，由系统维护场景图，相比 WinForms 的 GDI 绘制更灵活、更利于样式化。UI 线程负责渲染与交互，用 `Dispatcher` 与线程交互。

---

### 27. 什么是依赖属性（DependencyProperty）？和普通属性区别？

**标准答法：**
- 依赖属性是 WPF 专门设计的属性系统，**值存储在依赖属性字典中**而非字段，支持**值继承、数据绑定、样式、动画、默认值变更回调**。
- 与普通属性区别：普通属性用字段存储、无绑定/样式能力；依赖属性用 `DependencyObject` 的 `GetValue/SetValue` 访问，能参与**绑定、样式、模板、动画**。
- 声明方式：静态 `DependencyProperty.Register`，实例属性包装 `GetValue/SetValue`。

**加分点：** 依赖属性提供**属性值优先级**（本地值 > 样式 > 模板 > 默认值），这是面试加分点。常用场景：自定义控件、让属性支持绑定和动画。凡是需要参与绑定的自定义属性都应定义为依赖属性。

---

### 28. 什么是附加属性（Attached Property）？

**标准答法：**
- 附加属性是依赖属性的一种，**定义在别的类型上，却能附加到其他元素**，用于父容器给子元素传递布局/行为信息。
- 经典例子：`Grid.Row`、`Grid.Column`、`Canvas.Left`、`DockPanel.Dock`。
- 本质：静态注册（`RegisterAttached`），通过 `Get/Set` 静态方法读写，值仍存在子元素的属性字典中。

**加分点：** 面试常问"`Grid.Row` 为什么能写在 `TextBlock` 上？"——因为它是 `Grid` 类型定义的附加属性，`TextBlock` 作为 DependencyObject 能保存这个附加值。这是依赖属性系统强大之处的体现。

---

### 29. 什么是路由事件（Routed Event）？与普通事件区别？

**标准答法：**
- 路由事件是 WPF 的**事件路由机制**，事件沿**元素树**传播，而非只针对触发元素本身。
- 三种路由策略：
  - **冒泡（Bubbling）**：从触发元素沿树向上传播到根（默认，如 `Click`）。
  - **隧道（Tunneling）**：从根向下传播到触发元素（如 `PreviewMouseDown`），先于冒泡。
  - **直接（Direct）**：只作用于自身。
- 用途：父元素统一处理子元素事件、命令路由。

**加分点：** **隧道与冒泡成对出现**——`PreviewMouseDown`（隧道）先于 `MouseDown`（冒泡）。`e.Handled = true` 可停止路由。经典面试："点击 Button，Click 事件在哪处理？"——利用冒泡可在父容器统一挂处理。

---

### 30. 什么是数据绑定（DataBinding）？Mode 有哪些？

**标准答法：**
- 数据绑定是 WPF 的核心，将 UI 属性与数据源（ViewModel 属性）关联，数据变化自动更新 UI，UI 变化也回写数据，实现**UI 与逻辑解耦**。
- 语法：`{Binding Path=属性, Mode=..., UpdateSourceTrigger=...}`。
- Mode：
  - **OneWay**：源→目标（数据变化更新 UI）。
  - **TwoWay**：双向（默认给可编辑控件，如 TextBox 的 Text）。
  - **OneTime**：仅初始一次，性能最好。
  - **OneWayToSource**：目标→源。
- **UpdateSourceTrigger**：`PropertyChanged`（输入即更新源）、`LostFocus`（失焦更新，TextBox 默认）、`Explicit`。

**加分点：** 绑定生效前提：数据源需实现 `INotifyPropertyChanged`，否则 UI 不会自动更新（这是 MVVM 关键）。也可用 `INotifyPropertyChanged` 基类封装 `SetProperty` 简化。

---

### 31. 什么是 INotifyPropertyChanged？为什么 MVVM 需要它？

**标准答法：**
- `INotifyPropertyChanged` 是让**对象属性变化时通知 UI** 的接口，包含 `PropertyChanged` 事件。
- 在属性 setter 中触发 `PropertyChanged`，绑定机制收到通知后刷新界面。
- **为什么需要**：WPF 绑定默认只读一次/显式刷新，若属性变化不通知，UI 不会更新；实现该接口才能让 UI 与数据**实时同步**。

**加分点：** 完整实现示例（背住）：
```csharp
public class ViewModelBase : INotifyPropertyChanged
{
    public event PropertyChangedEventHandler PropertyChanged;
    protected void OnPropertyChanged([CallerMemberName] string name = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));
}
```
`[CallerMemberName]` 让调用处自动传属性名，避免手写字符串。

### 32. 什么是 MVVM？为什么用它？

**标准答法：**
- MVVM（Model-View-ViewModel）是一种架构模式，三层：
  - **View**：界面（XAML），只负责展示与交互，不含业务逻辑。
  - **ViewModel**：界面状态与行为，暴露属性/命令给 View 绑定，实现 INotifyPropertyChanged。
  - **Model**：数据模型与业务逻辑/服务。
- 优点：**UI 与逻辑解耦**、**可测试性高**（ViewModel 可单测）、**可维护性好**、便于分工与复用。

**加分点：** WPF 数据绑定 + 命令（`ICommand`）+ 依赖属性正是为 MVVM 设计的。面试常问"View 怎么通知 ViewModel"——通过绑定命令（`Command`）或事件转命令（`EventToCommand`/Behavior）。

### 33. 什么是命令（ICommand）？RelayCommand 是什么？

**标准答法：**
- `ICommand` 接口：`Execute`（执行）、`CanExecute`（能否执行）、`CanExecuteChanged`（执行状态变化通知）。
- 用于把 UI 的按钮点击等动作**绑定到 ViewModel 的方法**，替代事件处理器，解耦 UI 与逻辑。
- `RelayCommand`：`ICommand` 的通用实现，把执行逻辑封装成委托（`Action`/`Func`），是 MVVM 中最常用的命令实现。

**加分点：** 背住 RelayCommand 简洁实现：
```csharp
public class RelayCommand : ICommand
{
    private readonly Action<object> _execute;
    private readonly Predicate<object> _canExecute;
    public RelayCommand(Action<object> exec, Predicate<object> can = null)
    { _execute = exec; _canExecute = can; }
    public bool CanExecute(object p) => _canExecute?.Invoke(p) ?? true;
    public void Execute(object p) => _execute(p);
    public event EventHandler CanExecuteChanged
    {
        add => CommandManager.RequerySuggested += value;
        remove => CommandManager.RequerySuggested -= value;
    }
}
```
`CanExecuteChanged` 用 `CommandManager.RequerySuggested` 让 WPF 自动重新评估。

### 34. 什么是触发器（Trigger）、模板（Template）？

**标准答法：**
- **触发器（Trigger）**：当属性/事件/数据满足条件时改变样式或行为。类型：`Trigger`（属性）、`DataTrigger`（数据）、`EventTrigger`（事件）、`MultiTrigger`（多条件）。
- **模板（Template）**：
  - `ControlTemplate`：重定义控件的**外观结构**（控件长什么样），配合 `TemplateBinding` 绑定模板属性。
  - `DataTemplate`：定义**数据显示方式**（数据呈现成什么 UI），常用在 `ListBox/DataGrid` 的 ItemTemplate。
  - `ItemsPanelTemplate`：定义 ItemsControl 的布局面板。

**加分点：** 核心区别——`ControlTemplate` 管"控件长相"，`DataTemplate` 管"数据长什么样"。面试常考"如何完全重绘一个 Button"——用 `ControlTemplate` + `Trigger` 实现悬停/按下效果。

### 35. 什么是样式（Style）？如何继承与复用？

**标准答法：**
- `Style` 用于为一组控件统一定义属性值，实现界面一致性。
- 通过 `Setter` 设置属性，`TargetType` 指定目标控件类型。
- **基于样式**（`BasedOn`）实现样式继承复用。
- 可定义**隐式样式**（无 Key，作用于所有同类型控件）和**显式样式**（有 Key，通过 `Style` 引用）。

**加分点：** 样式优先级低于本地属性值（依赖属性优先级）；"主题化/换肤"常通过合并资源字典 + 全局样式实现。示例：
```xml
<Style TargetType="Button">
    <Setter Property="Background" Value="#14665B"/>
</Style>
<Style x:Key="BtnPrimary" TargetType="Button" BasedOn="{StaticResource {x:Type Button}}">
    <Setter Property="Foreground" Value="White"/>
</Style>
```

### 36. 什么是资源（Resource）？StaticResource 和 DynamicResource 的区别？

**标准答法：**
- 资源（`Resources`）是 WPF 中可复用的对象（样式、模板、画刷、颜色等），定义在资源字典中，按**层级查找**（自下而上）。
- **StaticResource**：编译期/加载期解析一次，引用对象后**不随资源变化更新**，性能好。
- **DynamicResource**：运行时动态解析，**资源变化时自动更新**，支持运行时换肤，性能稍差。

**加分点：** 动态资源适合主题切换（换肤）。注意 StaticResource 引用必须在资源定义之后；DynamicResource 无此限制。依赖属性优先级中，DynamicResource 更新优先级高于 StaticResource。

### 37. 什么是 Dispatcher？WPF 中如何跨线程更新 UI？

**标准答法：**
- WPF 的 UI 元素有**线程亲和性**，只能在创建它的 **UI 线程**上访问；其他线程直接改 UI 会抛异常。
- **Dispatcher**：WPF 的**消息循环**，负责在 UI 线程上排队和执行任务。
- 跨线程更新 UI 两种方式：
  - `Dispatcher.Invoke`（同步，阻塞直到执行完）。
  - `Dispatcher.BeginInvoke`（异步，排队后立即返回）。
  - `Task`/`async` 的 `await` 后自动回到 UI 同步上下文（WPF 默认），所以 `await` 后可直接更新 UI。

**加分点：** 典型场景——后台线程采集到数据，需用 `Dispatcher.Invoke` 更新界面。也常问 `Dispatcher.Invoke` 与 `BeginInvoke` 的区别（同步 vs 异步、是否等待）。`async/await` 的 `ConfigureAwait(false)` 会导致不回到 UI 线程，此时需手动 `Dispatcher`。

### 38. WPF 中常用布局控件？各自特点？

**标准答法：**
- `Grid`：网格布局，可定义行列（最常用、最灵活）。
- `StackPanel`：垂直/水平堆叠排列。
- `DockPanel`：停靠布局（上/下/左/右/填充）。
- `WrapPanel`：自动换行排列（类似流式）。
- `Canvas`：绝对坐标定位。
- `UniformGrid`：均分网格。
- 容器选择原则：用 `Grid` 做整体框架，用 `StackPanel` 做简单堆叠，用 `DockPanel` 做停靠。

**加分点：** 面试常问"`Grid` 与 `StackPanel` 区别"——`Grid` 按行列定位可跨行列，`StackPanel` 只按顺序堆叠；`Grid` 的 `*` 与 `Auto` 尺寸分配。

### 39. DataGrid / ListBox 绑定数据常用做法？

**标准答法：**
- 通过 `ItemsSource` 绑定一个集合（通常 `ObservableCollection<T>`），配合 `DataTemplate` 定义每项显示。
- `DataGrid` 自动生成列（`AutoGenerateColumns`）或手动定义 `DataGridTextColumn/DataGridComboBoxColumn/DataGridTemplateColumn`。
- `SelectedItem` 双向绑定当前选中项。
- 集合变化通知：用 **`ObservableCollection<T>`**（实现 `INotifyCollectionChanged`），增删自动刷新 UI。

**加分点：** 面试高频点——"为什么集合用 `ObservableCollection` 而不是 `List`？"——因为 `List` 增删不通知 UI 更新，`ObservableCollection` 实现 `INotifyCollectionChanged`，增删会实时刷新。给 `List` 重新赋值 `ItemsSource` 也会刷新，但增删单项不会。

### 40. 什么是虚拟化？DataGrid 数据多时如何优化？

**标准答法：**
- 虚拟化（UI Virtualization）：只实例化**可见区域**的 UI 元素，滚动时按需创建/回收，避免大量数据时创建海量控件导致卡顿。
- 开启方式：`VirtualizingStackPanel.IsVirtualizing="True"`，`ScrollViewer` 的容器用 `VirtualizingStackPanel`（DataGrid/ListView 默认开启，需在滚动面板内才生效）。
- 数据侧优化：分页加载、`ObservableCollection` 增量加载、只绑定需要的字段。

**加分点：** 虚拟化失效常见原因——`StackPanel` 作为 `ItemsPanel`（应改用 `VirtualizingStackPanel`）、未在 `ScrollViewer` 内。`IsVirtualizing="True"` + `VirtualizationMode="Recycling"`（回收复用）性能最好。MES 大列表（如历史追溯、报表）常用分页 + 虚拟化。

### 41. 缓存过期、并发下的数据一致性你怎么处理？（MES 场景）

**标准答法：**
- 多用户并发报工/扣料/质检时，用**数据库事务 + 锁**保证一致性。
- 方案：
  - 乐观锁：`Version`/`RowVersion` 字段，更新时校验版本，冲突则重试或提示。
  - 悲观锁：`select ... for update`，`lock`/`Monitor` 保护共享内存状态。
  - 数据库唯一约束兜底（防止重复报工/重复扣料）。
- 报工数量校验、库存扣减放在**同一个事务**，保证原子性。

**加分点：** 结合 MES——"多工位同时报工扣料，用事务 + 行级锁保证库存不超扣，用唯一键防止同一序列号重复扫描入库"。WPF 端多线程更新同一集合时用 `ConcurrentDictionary` 或 `lock`。

### 43. 说说你参与的一个项目，你在其中负责什么？（STAR 法则）

### 44. 进程与线程的区别？.NET 中如何选择？

**标准答法：**
- **进程**：操作系统资源分配的最小单位，拥有独立内存空间，进程间隔离。
- **线程**：CPU 调度的最小单位，属于进程，同进程线程共享内存（易并发冲突）。
- .NET 线程模型：`Thread`、`ThreadPool`、`Task`、`async/await`、`Parallel`、`lock`/信号量。

**加分点：** 面试常问"为什么用 `Task` 不用 `Thread`"——`Task` 底层用线程池，自动管理线程数、支持取消/等待/延续，配合 `async/await` 更优雅；`Thread` 需手动管理生命周期。CPU 密集用 `Parallel.For`/`Task.Run`，I/O 密集用 `async/await`。

### 45. 什么是死锁？如何避免？

**标准答法：**
- 死锁：多个线程互相持有对方需要的锁且等待对方释放，导致永久阻塞。
- 四个必要条件：互斥、持有并等待、不可剥夺、循环等待。
- 避免方法：
  - **加锁顺序一致**（按固定顺序获取锁）。
  - 用 `Monitor.TryEnter`/`Semaphore` 超时获取，失败则释放已有锁。
  - 减少锁的持有时间、缩小锁粒度。
  - 尽量用无锁结构（`Interlocked`、`Concurrent` 集合）。

**加分点：** WPF 场景常因 `Dispatcher.Invoke` 与后台线程互相等待 UI/资源造成死锁，避免在 UI 线程同步等待后台任务（用 `await` 而非 `.Result`/`.Wait()`）——这是高频坑。

---

### 46. `Task.Run`、`async/await`、`Parallel.For` 三者的使用场景？

**标准答法：**
- `Task.Run`：把同步/CPU 密集代码丢到线程池异步执行，返回 `Task`。
- `async/await`：用于 I/O 密集（数据库、网络、文件），不阻塞线程，真正异步。
- `Parallel.For/ForEach`：CPU 密集的**并行处理**大数据集，充分利用多核（如批量数据处理）。

**加分点：** 面试常考"为什么数据库查询用 `async/await` 而不是 `Task.Run`"——因为 I/O 本身异步、不占线程，`Task.Run` 反而多一次线程调度开销；`async/await` 让调用线程立即释放处理其他任务。注意 `Parallel` 不保证顺序、不适合共享状态写入。

## 第六部分：C# 深度进阶（51–63）

### 51. struct 和 class 的区别？什么时候该用 struct？

**标准答法：**
- `class`：引用类型，堆分配，可继承，可为 null，支持析构/终结器，适合有身份、需要共享状态的对象。
- `struct`：值类型，栈上（或内嵌在对象里），拷贝语义，不能继承（只能实现接口），不能为 null（除非 `Nullable<T>`），适合**小而短命、值语义**的数据（坐标、颜色、金额、时间范围）。
- 判断标准：**是否需要"身份"**。两个相同内容的对象若应视为同一个实体 → class；若"内容相同即等价" → struct。

**加分点：** struct 的三个坑：① 默认构造函数不能自定义（C# 10 后可有参数化构造）；② 可变 struct 作为属性/集合元素时，修改的是副本；③ 大 struct 传参拷贝开销大，应配合 `readonly struct` + `in`。微软建议 struct 大小控制在 16~24 字节以内。

---

### 52. record 和 record struct 是什么？解决了什么问题？

**标准答法：**
- `record`（C# 9）：引用类型的"值语义类"，编译器自动生成：构造函数、`Equals`/`GetHashCode`（按所有属性逐字段比较）、`ToString`、`with` 表达式（浅拷贝并改部分属性）、解构。
- `record struct`（C# 10）：值类型版本，同样有值语义与 `with`。
- 用途：DTO、配置对象、不可变数据模型、需要"按内容相等"的场景。

**加分点：** record 默认属性是 `init`（只能在初始化时赋值），天然适合不可变设计；`with` 是**浅拷贝**，引用类型字段仍共享。record 的相等比较是逐字段的，class 默认是引用比较——这是它最有价值的差异。

---

### 53. 什么是可空引用类型（Nullable Reference Types）？

**标准答法：**
- C# 8 引入的**编译期**空值检查：`string` 表示"不应为 null"，`string?` 表示"可能为 null"。
- 编译器据此给出警告（如解引用可能为 null 的值），帮助在编码阶段发现 NRE（空引用异常）。
- **运行时行为不变**：它只是静态分析注解 + 警告，不会自动插入判空。

**加分点：** 常见配套：`!`（null-forgiving，告诉编译器"我保证不为 null"）、`?.`/`??`/`??=`、`required` 成员（C# 11 强制初始化）。开启方式：项目文件 `<Nullable>enable</Nullable>`。

---

### 54. `yield return` 的原理？什么是迭代器？

**标准答法：**
- `yield return` 让方法变成**迭代器**，编译器生成一个状态机类（实现 `IEnumerable<T>`/`IEnumerator<T>`），**按需逐个产出元素**，不是一次性算完。
- 特点：**延迟执行**、**惰性求值**、内存友好（可处理大数据流/无限序列）。
- 每次 `MoveNext()` 恢复到上次 `yield` 的位置继续执行。

**加分点：** 经典陷阱——`yield` 方法里的 `try/finally` 会在枚举结束/提前 break 时执行 finally；延迟执行意味着"方法调用时不执行、枚举时才执行"，若方法内有副作用需注意。这也是 LINQ 延迟执行的技术基础。

---

### 55. 什么是表达式树（Expression Tree）？

**标准答法：**
- `Expression<TDelegate>` 把 lambda 的**代码结构**编译成对象树（而非直接编译成委托），可以遍历、分析、改写。
- 用途：LINQ to SQL / EF Core 把表达式翻译成 SQL；动态构建查询条件；规则引擎。
- `Expression` 可通过 `.Compile()` 生成为可执行委托。

**加分点：** `IQueryable` 的 `Where(x => ...)` 接收的是 `Expression<Func<T,bool>>` 而不是 `Func<T,bool>`，正是为了能翻译成 SQL。动态拼接条件常用 `Expression<Func<T,bool>>` 组合（And/Or 改写），比字符串拼 SQL 安全。

---

### 56. 扩展方法是什么？有什么限制？

**标准答法：**
- 扩展方法允许给已有类型"追加"方法调用语法，定义在**静态类**中、方法第一个参数带 `this` 修饰符。
- 例：`public static string ToMd5(this string s)`，调用 `s.ToMd5()`。
- 限制：只能定义在静态类；不能访问私有成员；不参与重载解析的优先级高于实例方法（实例方法优先）；不能用于扩展字段/属性。

**加分点：** 常用于框架（Furion、EF、LINQ）的链式 API 设计。若同时存在实例方法与扩展方法，**实例方法优先**。扩展方法本质是静态方法调用，编译期绑定。

---

### 57. 静态构造函数、partial 类、嵌套类的要点？

**标准答法：**
- **静态构造函数**：类首次被使用时（首次访问静态成员/创建实例）自动执行一次，无访问修饰符、无参数，不能手动调用。
- **partial 类**：把一个类拆成多个文件定义，编译时合并；常用于把自动生成的代码与手写代码分离（如 WPF 的 XAML + Code-Behind、EF 生成实体）。
- **嵌套类**：定义在类内部的类，可访问外部类的私有成员（同程序集内），用于逻辑归组。

**加分点：** 静态构造函数的执行时机由 CLR 保证**线程安全且只执行一次**，是"静态内部类单例"的实现基础。partial 方法（C# 9）可在 partial 类中声明/实现分离。

### 58. C# 的模式匹配有哪些用法？

**标准答法：**
- `is` 类型模式：`if (obj is string s && s.Length > 0)`，判断并赋值。
- `switch` 表达式与模式：类型模式 `case int i:`、常量模式、属性模式 `case Person { Age: > 18 } p:`、位置模式（配合解构）、`when` 守卫条件。
- C# 8 起支持 `switch` 表达式（返回值形式）、`and/or/not` 组合模式。

**加分点：** 模式匹配是 C# 现代写法的核心，适合替代大量 if-else 类型判断（如 MES 中按设备类型分派不同采集逻辑）。`switch` 表达式可读性和穷尽性（配合 sealed 类型）优于传统 switch。

### 59. .NET 的 GC 有哪几种模式？什么是内存碎片与压缩？

**标准答法：**
- **工作站 GC（Workstation）**：单线程回收，适合客户端应用（WPF 桌面程序默认）。
- **服务器 GC（Server）**：多线程并行回收、按 CPU 分堆，适合高吞吐服务端（ASP.NET Core 可配置）。
- **并发/后台 GC（Background GC）**：第 2 代回收在后台线程进行，减少停顿（低延迟场景）。
- **压缩（Compact）**：回收后移动存活对象、整理空间，消除碎片；LOH 默认不压缩（可配置 `GCSettings.LargeObjectHeapCompactionMode`）。
- **固定对象（Pinned）**：被 pin 的对象不能移动，会阻碍压缩、产生碎片。

**加分点：** 面试常问"为什么高频创建大对象不好"——LOH 不压缩、易碎片化。MES 高频采集数据对象建议复用/池化（`ArrayPool`/对象池），避免 GC 压力。

### 60. `Span<T>`、`Memory<T>`、`ArrayPool` 是干什么的？

**标准答法：**
- `Span<T>`：栈上的**连续内存视图**，可零拷贝切片访问数组/字符串/非托管内存，`ref struct`（不能存堆、不能跨 `await`、不能作为字段）。
- `Memory<T>`：`Span<T>` 的堆友好版本，可跨 `await`、可存字段。
- `ArrayPool<T>`：数组池，复用数组避免频繁分配/回收，`Rent()`/`Return()` 成对使用。

**加分点：** 适合高频、大数据量场景（如设备报文解析、字符串切片）。注意 `Span` 的生命周期约束，`stackalloc` 配合 `Span` 可栈上分配临时缓冲。坑：`ArrayPool` 归还后不可再使用；数组内容不保证清零。

### 61. 单例模式有几种实现？哪种最好？

**标准答法：**
1. **饿汉式**：静态字段直接 `new`，类加载即创建，简单但可能浪费。
2. **懒汉式 + 双重检查锁（DCL）**：`volatile` + `lock` + 判空，线程安全但有锁开销。
3. **静态内部类/静态字段初始化**：利用 CLR"类型初始化只执行一次且线程安全"的特性，**延迟加载 + 无锁**，最推荐。
4. **`Lazy<T>`**：`LazyThreadSafetyMode.ExecutionAndPublication`，语义清晰、线程安全，工程上最常用。

**加分点：** C# 里静态字段初始化优于手写 DCL——因为 CLR 的类型初始化本身是线程安全的，不需要 `volatile`/`lock`。反例：`lock (this)` 或 `lock (typeof(X))` 是坏实践（外部可锁同一对象）。

### 62. `const`、`readonly`、`static readonly` 的区别？

**标准答法：**
- `const`：**编译期常量**，只能是基本类型/string/枚举，编译时直接替换为字面值，隐式 static，不能跨程序集动态更新（改了需重编译所有引用方）。
- `readonly`：**运行期只读**，可在声明处或构造函数中赋值一次，运行时才确定值，可用于任意类型（含引用类型/对象）。
- `static readonly`：静态只读字段，类级别，同样运行期赋值。

**加分点：** 关键差异是"替换语义"：`const` 在引用方内联，若 DLL 中改了 const 而引用方未重编译，会读到旧值——这是经典坑。跨程序集传值优先用 `static readonly`。

---

### 63. `var` 与显式类型、`dynamic` 的区别？

**标准答法：**
- `var`：**编译期类型推断**，仍是强类型，编译后类型固定，只是少写类型名，无运行时开销。
- `dynamic`：**运行时动态类型**，调用在运行时通过 DLR 绑定，可调用任意成员，类型错误在运行时才暴露，有性能开销。
- 选择：`var` 用于类型明显/冗长场景（如 `new List<Order>()`）；`dynamic` 用于 COM 互操作、动态脚本、弱类型场景，业务代码尽量不用。

**加分点：** `dynamic` 与 `object` 区别——`object` 调用成员需强转/反射，`dynamic` 直接调用（内部走反射缓存）。`var` 不能用于字段、参数、返回值。

## 第七部分：.NET / ASP.NET Core / 框架与中间件（64–78）

### 64. ASP.NET Core 的请求管道与中间件机制？

**标准答法：**
- 请求进入后经过一条**中间件管道**（Middleware Pipeline），每个中间件是 `RequestDelegate`（`HttpContext` → `Task`），可：处理请求、调用 `next()` 继续、短路（不调 next）。
- 注册：`app.Use(...)`（可继续）、`app.Run(...)`（终端中间件）、`app.Map(...)`（分支）。
- **顺序决定行为**：认证 → 授权 → 路由 → 业务 通常有固定顺序；异常处理中间件必须在最外层。

**加分点：** 中间件是"洋葱模型"，请求正序进入、响应逆序返回。常见考点：`Use` 与 `Run` 区别、为什么异常处理要放最前、如何写自定义中间件（实现 `IMiddleware` 或 `Invoke` 方法）。MES 中可用中间件做统一日志、租户识别、接口耗时统计。

### 65. DI 三种生命周期在 Web/WPF 场景下分别怎么用？

**标准答法：**
- **Singleton**：全局唯一，进程级共享（配置、缓存管理器、连接池）。要注意线程安全。
- **Scoped**：每个**请求**（ASP.NET Core 的 HttpContext 作用域）一个实例，适合 DbContext、请求级上下文。
- **Transient**：每次解析都新建，适合轻量无状态服务。

**加分点：** 两大坑：① **Singleton 依赖 Scoped**（"captive dependency"）——Scoped 会被提升为长寿对象，导致 DbContext 复用、状态污染；② **WPF 没有 HTTP 请求作用域**，要自己 `IServiceScopeFactory.CreateScope()` 手动开作用域，否则 Scoped 退化成单例行为。

### 67. JWT 认证流程？如何处理注销/失效？

**标准答法：**
- **JWT 结构**：`Header.Payload.Signature` 三段 Base64，Payload 存声明（用户 ID、角色、过期时间），签名用密钥保证不可篡改。
- 流程：登录校验账号密码 → 签发 Token → 客户端每次请求带 `Authorization: Bearer <token>` → 服务端验签 + 校验过期 → 解析用户身份。
- **无状态**的代价：服务端不存会话，天然难"立即失效"。

**加分点：** 注销方案：① 客户端删除 Token（治标）；② 服务端维护**黑名单/Token 版本号**（Redis 存失效 Token 或用户版本号）；③ 短有效期 AccessToken + RefreshToken 刷新机制。MES 中权限严格，常配合 Redis 黑名单实现强制下线。

### 68. SignalR 是什么？MES 实时看板怎么用？

**标准答法：**
- SignalR 是 ASP.NET Core 的**实时双向通信**库，底层自动协商 WebSocket / Server-Sent Events / 长轮询。
- 核心概念：`Hub`（服务端集线器）、`Clients.All/Specific`（推送目标）、`Client → Server` 调用方法。
- 场景：实时看板（产量、OEE、报警）、消息通知、协同编辑。

**加分点：** MES 典型用法：设备采集数据变化 → 服务端通过 Hub 主动 Push 到 WPF 看板客户端，避免前端轮询。注意**背压/节流**——高频数据要做聚合（如每 500ms 推一次或变化才推），否则客户端被刷爆；集群部署需 **Redis backplane** 让多节点广播。

---

### 69. gRPC 与 REST 的区别？MES 里如何选？

**标准答法：**
- **REST**：HTTP/1.1 + JSON，文本、通用、易调试，适合对外 API / 前端调用。
- **gRPC**：HTTP/2 + Protobuf，二进制、强类型契约、高效、支持流式，适合**服务间高频调用**（内部微服务）。
- 选择：对外/给浏览器用 REST；内部高频、低延迟、强契约用 gRPC。

**加分点：** MES 场景——MES 与 SCADA/采集服务之间高频数据交互可用 gRPC（效率高、支持流式），给前端看板/移动端用 REST。gRPC 缺点：浏览器支持弱（需 gRPC-Web）、调试不如 JSON 直观。

---

### 70. Redis 在 MES 中的典型用法？

**标准答法：**
1. **缓存**：主数据（物料、BOM）、字典、设备状态，减少数据库压力。
2. **分布式锁**：多节点并发抢同一工位/库存（`SET key value NX PX`，需考虑锁续期与释放原子性）。
3. **Redis Stream**：轻量消息队列，用于采集数据缓冲、异步处理、多消费者。
4. **计数/限流**：产量计数、接口限流（令牌桶）。
5. **会话/Token 黑名单**：JWT 失效管理。

**加分点：** 分布式锁必须答出"加锁 + 超时 + 锁标识校验 + Lua 原子释放"，否则会被追问死锁/误删。Redis Stream 用 `XADD`/`XREADGROUP`/`XACK` 实现消费组，天然支持多消费者与 ACK，比 Pub/Sub（不持久、不保证送达）更适合业务消息。

---

### 71. 消息队列的幂等与顺序问题怎么解决？

**标准答法：**
- **幂等**：消费者可能重复收到消息，需保证同一消息处理多次结果一致。方案：
  - 业务唯一键 + 数据库唯一约束。
  - 消费前查"消息 ID 是否已处理"（Redis/去重表）。
  - 状态机控制（如工单"已报工"状态不允许重复报工）。
- **顺序**：单队列单消费者保证有序；或按业务键分区（同一工单的消息进同一分区）；或用版本号/序号校验乱序。

**加分点：** 不只是"加个唯一键"——要讲**至少一次（at-least-once）投递**是常态，所以消费端必须幂等。MES 中报工、扣料都必须幂等，否则重复上报导致库存错误。

---

### 72. 微服务怎么拆？MES 适合微服务吗？

**标准答法：**
- 拆分原则：按**业务边界/领域**（DDD 限界上下文）拆，高内聚低耦合，一个服务一个数据库。
- 不建议按技术层拆（Controller 服务/Service 服务）。
- MES 特点：业务强关联、事务多、实时性要求高、客户多为单厂部署。

**加分点：** 诚实的答法：**中小型 MES 单体架构更合适**（部署简单、事务一致、运维成本低），用模块化（模块内高内聚）代替微服务；只有多工厂/多租户、超大规模时才考虑微服务。答"什么都拆微服务"会被认为不懂工程权衡。若拆，至少把**采集服务**（高频、独立伸缩）与**业务服务**分开。

---

### 73. 后台任务怎么做？`IHostedService` 与 `BackgroundService`？

**标准答法：**
- `IHostedService`：随应用启动/停止执行的后台服务接口（`StartAsync`/`StopAsync`）。
- `BackgroundService`：继承自 `IHostedService`，封装了 `ExecuteAsync` 循环，最常用。
- 用途：定时任务、消息消费、数据同步、设备心跳检测。

**加分点：** 要点：① 后台服务内**不能用 Scoped 服务直接注入**，要用 `IServiceScopeFactory` 开作用域；② 要处理异常不中断循环；③ 优雅停止用 `CancellationToken`；④ 与 Furion 定时任务、Hangfire/Quartz 的选择（简单周期用 BackgroundService，复杂调度用 Quartz）。

---

### 74. 配置管理与日志怎么做？

**标准答法：**
- **配置**：`appsettings.json` + 环境变量 + 命令行，分层覆盖；用 `IOptions<T>`（单例快照）、`IOptionsSnapshot<T>`（Scoped，请求内一致）、`IOptionsMonitor<T>`（变更可监听）。
- **日志**：内置 `ILogger<T>` 抽象，实现用 Serilog / NLog；结构化日志（JSON）+ 分级（Debug/Info/Warn/Error）+ 输出到文件/ELK。

**加分点：** MES 现场要求**日志可追溯**：关键业务操作（报工、改参数、权限变更）要写**操作审计日志**（谁、何时、改了什么、原值/新值），与普通运行日志分开存储，保存期限按客户要求（常见 1~3 年）。

---

### 75. 接口幂等怎么设计？

**标准答法：**
- 场景：网络重试、用户重复点击、消息重投导致的重复提交。
- 方案：
  1. **唯一业务键 + 唯一索引**（最可靠，数据库兜底）。
  2. **幂等 Token**：先申请 Token，提交时校验并消费（Redis `SETNX`）。
  3. **状态机**：只允许特定状态流转（如"待报工 → 已报工"不可逆）。
  4. **去重表/Redis 记录请求 ID**（带过期时间）。

**加分点：** 面试常追问"分布式下唯一索引还够吗"——够，因为唯一约束是数据库全局的，是最后一道防线；Redis 去重只是前置优化。MES 中扫同一序列号重复入库用唯一索引直接拦住，比应用层判断更可靠。

---

### 76. 大文件上传/下载怎么处理？

**标准答法：**
- 上传：**分片上传**（切片 + 并发 + 断点续传 + 合并校验），用文件 MD5 做秒传与完整性校验。
- 下载：**流式输出**（`Stream`/`FileStreamResult`），避免一次性读入内存。
- 存储：对象存储（MinIO/OSS）优于数据库存二进制。

**加分点：** 关键点：分片大小、并发数、合并时的顺序与校验、断点续传记录（Redis/数据库存已上传分片）。MES 中图纸/工艺文件（大 PDF/CAD）常用 MinIO + 分片上传，配合权限校验防止越权下载。

---

### 77. 如何设计统一返回结构、全局异常处理和参数校验？

**标准答法：**
- **统一返回**：`{ code, message, data, traceId }`，成功/失败统一，便于前端处理。
- **全局异常**：`IExceptionFilter` / 中间件捕获未处理异常，按异常类型映射 HTTP 状态码与业务码，记录日志并返回友好消息（不暴露堆栈）。
- **参数校验**：DataAnnotations（`[Required]`）+ FluentValidation，模型绑定失败统一返回校验错误。

**加分点：** 原则：**对外不泄露内部细节**（堆栈、SQL、路径），但要带 `traceId` 便于排查；业务异常（可预期）与系统异常（不可预期）区分处理，前者返回明确提示，后者统一兜底 + 告警。

---

### 78. OPC UA 在 .NET 中怎么接入？

**标准答法：**
- OPC UA 是工业通信标准：信息模型（节点、变量、对象）+ 安全（证书/加密）+ 跨平台。
- .NET 常用库：`OPCFoundation.NetStandard.Opc.Ua`（官方）、或第三方封装。
- 流程：建立 Session（Endpoint + 安全策略 + 证书）→ 浏览节点 → 订阅（Subscription + MonitoredItem，服务端变化才推送）→ 读/写 → 断线重连。

**加分点：** 面试重点在"**订阅优于轮询**"——MonitoredItem 设置采样间隔与死区（DeadBand），数据变化才上报，大幅降负载。还要讲**断线重连 + 重订阅**、证书信任配置、批量读写。MES 采集涂布机/卷绕机参数就是这套。

## 第八部分：数据库与 SQL（79–88）

### 79. 索引的原理与优化？

**标准答法：**
- 主流索引是 **B+ 树**：非叶子节点只存键、叶子节点存数据/指针且相互链接，适合范围查询与排序。
- **聚簇索引**（主键）：叶子节点即数据行（InnoDB）；**非聚簇索引（二级索引）**：叶子存主键值，需**回表**。
- 优化原则：**最左前缀**（联合索引按定义顺序匹配）、**覆盖索引**（查询字段都在索引中，免回表）、选择性高的列建索引、避免在索引列上做函数/运算、避免 `%前缀` 模糊。

**加分点：** 高频追问：① 为什么用 B+ 树不用 B 树/哈希（范围查询 + 磁盘 IO 少）；② `EXPLAIN` 看 `type`/`key`/`rows`/`Extra`（`Using index` 覆盖索引、`Using filesort` 需优化）；③ 索引不是越多越好（写入放大、空间占用）。

---

### 80. 事务的 ACID 与隔离级别？

**标准答法：**
- **ACID**：原子性（Atomicity）、一致性（Consistency）、隔离性（Isolation）、持久性（Durability）。
- 隔离级别与问题：
  - **Read Uncommitted**：可能脏读。
  - **Read Committed**：避免脏读，可能不可重复读。
  - **Repeatable Read**：避免不可重复读，可能幻读（MySQL 默认，用 MVCC + 间隙锁基本解决幻读）。
  - **Serializable**：全串行，最安全最慢。
- 实现：锁（行锁/表锁）+ **MVCC**（多版本并发控制，快照读）。

**加分点：** MySQL 默认 RR、PostgreSQL/Oracle 默认 RC，这个差异常被问。MVCC 靠隐藏列（事务 ID、回滚指针）+ undo log 实现快照读；`SELECT ... FOR UPDATE` 是当前读，会加锁。

---

### 81. 数据库死锁怎么排查和避免？

**标准答法：**
- 成因：两个事务以不同顺序锁同一批行，相互等待。
- 排查：MySQL `SHOW ENGINE INNODB STATUS` 看最近死锁；开启死锁日志；应用日志看异常。
- 避免：**统一加锁顺序**、缩小事务范围（快进快出）、减少锁粒度（用行锁不用表锁）、避免长事务、必要时降低隔离级别、加锁语句尽量走索引（否则锁全表/大量行）。

**加分点：** 关键洞察：**没走索引的 `UPDATE` 会锁很多行甚至全表**，这是 MES 高并发写场景死锁的常见根因。事务内不要做远程调用/耗时操作（拉长持锁时间）。

---

### 82. 慢 SQL 怎么优化？（结合 MES 追溯查询）

**标准答法：**
- 定位：慢查询日志、`EXPLAIN`、`SHOW PROFILE`。
- 优化手段：加合适索引（联合索引、覆盖索引）、避免 `SELECT *`、分页（`LIMIT`）、避免 N+1、减少回表、拆分大事务、数据归档。
- MES 追溯案例：按"序列号/批次号 + 时间范围"查询 → 建 `(SerialNo, CreateTime)` 联合索引；大表按时间分区；历史数据归档到冷表。

**加分点：** 讲**量化结果**（如"10 秒 → 1 秒"）。还要注意：深分页 `LIMIT 100000, 20` 很慢，改 `WHERE id > lastId LIMIT 20`（游标分页）。

---

### 83. EF Core 与 ADO.NET 怎么选？ORM 的优缺点？

**标准答法：**
- **ADO.NET**：手写 SQL，完全可控、性能最好，但代码量大、易出错、维护成本高。
- **EF Core**：ORM，实体映射、LINQ 查询、迁移、变更跟踪；开发效率高，但复杂查询可能生成低效 SQL。
- 选择：简单 CRUD / 快速开发用 EF；复杂报表 / 高性能批量用 Dapper 或原生 SQL。

**加分点：** EF 的坑：① `Include` 过多导致笛卡尔积、N+1；② 延迟加载在循环中触发查询；③ 大批量插入用 `AddRange` 仍逐条，应 `ExecuteUpdate`/批量库；④ 长事务持有 DbContext。**混合使用（EF + Dapper）是务实答案**。

---

### 84. 主键怎么设计？自增 vs 雪花 ID？

**标准答法：**
- **自增 ID**：简单、有序、索引友好；缺点：分库分表冲突、ID 可被推测（泄露业务量）。
- **GUID/UUID**：全局唯一、可客户端生成；缺点：无序（随机）导致索引页分裂、存储大。
- **雪花 ID（Snowflake）**：`时间戳 + 机器 ID + 序列号`，趋势递增、全局唯一、高性能，适合分布式。

**加分点：** 雪花 ID 依赖**机器 ID 分配**（配置/注册中心）和**时钟回拨**处理，这两点必须提到，否则被认为只看过文章。MES 单库部署用自增即可，别为了"分布式"过度设计。

---

### 85. 乐观锁与悲观锁的 SQL 实现？

**标准答法：**
- **乐观锁**：读时不加锁，更新时校验版本：
  ```sql
  UPDATE t SET qty = qty - 1, version = version + 1
  WHERE id = 1 AND version = 3;
  ```
  影响行数 0 表示冲突，需重试或提示。
- **悲观锁**：读时即锁：`SELECT ... FOR UPDATE`（行锁），事务结束释放。

**加分点：** 乐观锁适合**读多写少、冲突少**；悲观锁适合**写冲突高、要求强一致**（如库存扣减、工位抢占）。乐观锁重试要有上限，避免活锁。MES 报工扣料常用乐观锁 + 唯一约束双保险。

---

### 86. 分表/分库怎么做？什么情况才需要？

**标准答法：**
- 触发条件：单表数据量过大（千万级）、单库写入/连接瓶颈、需要水平扩展。
- 方式：**垂直拆**（按业务/表拆库）、**水平拆**（按 hash/时间/范围分表）。
- 关键问题：路由规则、跨分片查询/聚合、分布式事务、全局唯一 ID、扩容迁移。

**加分点：** 诚实答案：**先优化（索引、归档、读写分离）再考虑分表**。MES 中真正需要分的是**采集数据表**（高频写入、海量），业务表通常不用拆。按时间分表 + 定期归档是工业场景最常见做法。

---

### 87. 设备高频采集数据怎么存？

**标准答法：**
- 特点：写入极高（秒级/毫秒级）、单条小、按时间查询、很少更新。
- 方案：
  1. **时序数据库**（InfluxDB/TDengine/IoTDB）：天然按时间索引、压缩率高。
  2. 关系库**分区表**（按天/月分区）+ 只保留必要字段。
  3. **先写 Redis/内存缓冲，批量落库**（降低 IO 次数）。
  4. 冷热分离：近期热数据查询、历史归档。

**加分点：** 关键设计：**批量写**（攒批 1000 条或 1 秒写一次）、**只存变化值**（死区过滤）、**异步解耦**（采集 → MQ → 落库）。MES 追溯需要的是"关键工艺参数 + 时间点"，不必存所有原始点，否则存储爆炸。

---

### 88. 存储过程该不该用？

**标准答法：**
- 优点：减少网络往返、逻辑集中、权限控制、批量处理快。
- 缺点：难维护/难版本控制、调试差、数据库绑定、迁移困难。
- 结论：**复杂批量计算可用，业务逻辑尽量放应用层**。

**加分点：** 现代工程倾向"应用层管逻辑、数据库管存储"，存储过程留给**报表统计、大批量数据迁移**。团队协作/CI 场景下存储过程难做代码审查和版本管理，是主要反对理由。

## 第九部分：MES 深化（89–104）

### 89. ISA-95 五层模型是什么？

**标准答法：**（工业信息化的标准分层，MES 面试必背）
- **Level 0 设备层**：传感器、执行器、PLC（物理生产过程）。
- **Level 1 控制层**：PLC/DCS，实时控制。
- **Level 2 监控层**：SCADA/HMI，数据采集与监控。
- **Level 3 制造执行层**：**MES**，工单执行、追溯、质量、设备管理。
- **Level 4 经营管理层**：ERP，计划、采购、财务、销售。
- （Level 5 可含企业间协同/供应链。）

**加分点：** 用一句话串起来："**0-1 层是设备自己跑，2 层看得见，3 层管得住，4 层算得清。**" 面试官问"MES 处在哪层"必须秒答 Level 3。

---

### 90. 工单的状态机怎么设计？

**标准答法：**
- 典型状态：`创建/待下达 → 已下达 → 执行中（生产中）→ 暂停/挂起 → 已完成 → 已关闭`，异常分支 `已取消`。
- 设计要点：**状态只能按允许路径流转**（如不可从"已完成"回退到"执行中"），流转时记录操作人、时间、原因（审计）。
- 实现：状态枚举 + 流转校验表/规则，数据库存当前状态 + 历史流水表。

**加分点：** 讲"**状态机 + 幂等**"组合：重复点击"开始生产"不应报错也不应重复开工（判断当前状态已满足则幂等返回）。工单状态直接影响报工、扣料、追溯的合法性，是 MES 数据一致性的核心。

---

### 91. 什么是 WIP？怎么管理？

**标准答法：**
- WIP（Work In Process，在制品）：已投产但未完工的产品/半成品，是车间在流转中的"库存"。
- 管理要点：每个工序的在制品数量、位置（工位）、状态（待加工/加工中/待检/合格/不良）、停留时间。
- 价值：**控制在制品数量（WIP 越少越好）**——减少资金占用、暴露瓶颈、缩短周期（精益思想）。

**加分点：** 用"利特尔法则"加分：`平均在制品 = 产出率 × 平均周期时间`。WIP 过多意味着瓶颈或批量过大。MES 通过报工/过站实时算 WIP，看板展示各工序堆积。

---

### 92. 批次管理和序列号（单件）管理的区别？

**标准答法：**
- **批次管理**：以"批"为单位（同一批投料/同一炉/同一时间生产），记录批次号，追溯粒度到批次。适合化工、食品、原料药。
- **序列号（SN）管理**：以"件"为单位，每件唯一编号，追溯粒度到单件。适合电子、汽车、锂电电芯/模组。
- 差异：SN 管理数据量更大、采集要求更高（每件每工序都要扫），但追溯精度最高。

**加分点：** 实际常**混用**：锂电是"电芯 SN + 物料批次"双维度——电芯有唯一 SN，同时绑定所用正极/电解液的批次号，这样既能查单件，也能反向查"某批电解液影响了哪些电芯"。这是最高频的追问点。

---

### 93. Andon（安灯）系统是什么？

**标准答法：**
- Andon 源自丰田，是**异常呼叫与可视化**机制：工位发现异常（缺料、质量问题、设备故障）时触发信号（灯/屏/声音），通知相关人快速响应。
- 分级：黄灯（求助/预警）、红灯（停线/严重）。
- 延伸：记录异常发生时间、类型、响应人、处理时长，形成**停线分析数据**。

**加分点：** Andon 不只是"亮个灯"——它的价值是**把异常变成可统计的数据**（响应时长、频次、Top 原因），支撑持续改善。MES 中 Andon 常与设备状态、质量判定联动，自动触发而非人工按灯。

---

### 94. MES 与 WMS 怎么集成？

**标准答法：**
- 分工：WMS 管**仓库内**的收货、上架、拣选、库存、发料；MES 管**车间内**的领料、投料、在制、退料。
- 接口场景：
  - MES 向 WMS 发**领料申请**（按工单 BOM）→ WMS 备料/发料 → 回传实发批次与数量。
  - 产成品完工 → MES 通知 WMS **入库**。
  - 退料/报废 → MES 通知 WMS 回库。
- 关键：**批次一致性**（MES 记录实际投入的物料批次，才能追溯）。

**加分点：** 常见问题：**账实不符**（WMS 发料与 MES 实际投料不一致），需以"实际扫描投料"为准并回写。接口要幂等、要有对账机制（按工单核对领料/投料/退料）。

---

### 95. MES 数据采集架构怎么设计？

**标准答法：**
- 分层：**设备层（PLC/传感器）→ 采集层（采集网关/SCADA）→ 平台层（MQ/Redis Stream）→ 应用层（MES 业务）**。
- 要点：采集层与业务层**解耦**（通过 MQ），避免设备抖动影响业务；批量/变化才上传；断线缓存补传。
- 协议：OPC UA、Modbus、MQTT、TCP 自定义报文。

**加分点：** 必须提到**断线重连与数据补传**（工业现场网络不稳定是常态），以及**时间同步**（设备时钟与服务器时钟不一致会导致追溯时间错乱，用 NTP 或记录采集时间戳兜底）。这两点是工业与互联网的最大差别。

---

### 96. 锂电产线的关键工序与 MES 控制点？

**标准答法：**（按典型锂电前中后段）
- **前段**：配料、涂布、辊压、分切 → 控制点：**面密度、厚度、张力、烘箱温度**（直接影响容量与安全）。
- **中段**：卷绕/叠片、入壳、焊接 → 控制点：**对齐度、短路测试、焊接参数**。
- **后段**：注液、化成、分容、老化、分选 → 控制点：**注液量、化成电流电压曲线、分容容量、内阻**。
- MES 贯穿：**SN 单件追溯 + 参数采集 + 不良判定 + 分选档位**。

**加分点：** 说清"**为什么锂电必须单件追溯**"——安全问题（电芯热失控需召回定位）+ 质量分析（容量/内阻与工艺参数关联）。分容分选要按容量/内阻**分档（Grade）**，MES 要记录档位并支持配组（同档电芯组模组）。

---

### 97. MES 的权限与审计怎么做？

**标准答法：**
- **权限**：RBAC（用户-角色-权限），细到**功能点/按钮/数据行**（如某车间只能看本车间工单）。
- **审计**：关键操作全记录（谁、何时、IP、操作类型、对象、原值、新值、结果），不可篡改（只追加）。
- 场景：改工艺参数、强制过站、改判质量、删除记录——这些高风险操作必须审批 + 留痕。

**加分点：** 工业客户（尤其车规/医疗）有**合规要求**（数据完整性、可追溯、不可否认）。"强制过站/改判"是审计重点，因为这是最容易出质量问题的人为操作，必须记录原因并追责。

---

### 98. MES 上线数据迁移怎么做？

**标准答法：**
- 步骤：梳理主数据（物料、BOM、工艺路线、设备、用户）→ 清洗（去重、补全、格式统一）→ 映射（旧系统字段 → 新系统字段）→ 试迁移（测试环境验证）→ 正式迁移（停机窗口）→ 核对（数量/关键字段比对）。
- 原则：**主数据先迁、业务数据后迁**；迁移脚本可重复执行（幂等）；保留原系统只读一段时间。

**加分点：** 最大风险是**主数据质量差**（一物多码、BOM 不准），很多 MES 项目失败根源在这里。务实做法：先做**主数据治理**，迁移前让业务部门确认；迁移后抽样核对 + 跑一遍完整业务流验证。

---

### 99. MES 如何保证高可用与稳定？

**标准答法：**
- 应用层：多实例 + 负载均衡；无状态设计（会话放 Redis）。
- 数据库：主从复制/读写分离、定期备份、故障切换。
- 采集层：断线缓存、消息队列削峰、限流。
- 运维：监控（CPU/内存/接口耗时/设备在线率）、告警、日志集中。

**加分点：** 工业现场的现实是**不能长时间停机**（停线损失巨大），所以更强调：**降级方案**（MES 挂了能否手工/离线报工，恢复后补录）、**本地缓存兜底**、**升级要能快速回滚**。

---

### 100. BOM 与替代料在 MES 中怎么处理？

**标准答法：**
- **BOM**（物料清单）：产品由哪些物料、各多少数量组成，分层（成品 → 半成品 → 原料）。
- MES 用 BOM 做**齐套检查**（物料是否够）和**投料防错**（扫的料是否在 BOM 内）。
- **替代料**：主料缺货时允许用替代料，需定义替代组、优先级、替代比例，且**必须记录实际用了哪个**（追溯要求）。

**加分点：** 关键点：BOM 要**版本化**（同一产品不同版本用料不同，追溯必须知道当时用的是哪版）；替代料的使用必须落到追溯记录里，否则出了质量问题查不清用了什么料。

### 101. MES 项目常见的验收指标？

**标准答法：**
- 功能：需求覆盖率高、关键流程跑通（工单→报工→追溯→报表）。
- 数据：追溯准确率（99%+）、采集完整率、账实一致率。
- 性能：页面响应时间、采集吞吐、并发用户数。
- 业务价值：OEE 提升、不良率下降、报表出数及时性、人工录入减少。

**加分点：** 面试答"验收"要落到**可量化指标 + 甲方签字确认的蓝图**。MES 项目纠纷多来自"需求边界不清"，所以要讲**蓝图确认、变更走流程**。

### 102. 讲一次你排查过的 MES 线上问题。

**标准答法（套 STAR + 排查链路）：**
- 现象：某工位报工偶发失败/数据重复。
- 定位：查日志（traceId）→ 发现并发重复提交 → 唯一键冲突 → 前端重复点击 + 网络重试。
- 解决：接口幂等（唯一键 + 状态机校验）+ 前端按钮防重 + 增加重试上限。
- 复盘：补充监控告警，规范所有报工接口走统一幂等组件。

**加分点：** 讲**排查方法论**（现象 → 日志 → 定位 → 修复 → 复盘 → 预防），比讲"我改了个 bug"有价值得多。体现你有工程闭环思维。

### 103. MES 与 SCADA 的分工？

**标准答法：**
- **SCADA**：面向**设备与过程**，实时采集、监控画面、报警、趋势，周期毫秒~秒级，偏"看"和"控"。
- **MES**：面向**生产业务**，工单、追溯、质量、物料、人员，周期分钟级，偏"管"。
- 关系：SCADA 采的数据一部分供 MES 使用（通过接口/MQ）；MES 下发工单/配方给 SCADA/设备。

**加分点：** 一句话：**SCADA 管"机器在干什么"，MES 管"这批货该怎么干、干得合不合格"。** 两者不是替代关系，是层级关系（Level 2 vs Level 3）。

---

### 104. 如果设备不支持 OPC UA，你怎么接入？

**标准答法：**
- 方案分层：① 设备有 Modbus/TCP → 网关转换；② 只有串口/私有协议 → 采集网关（解析报文）；③ 老旧设备无通讯口 → 加装 IO 模块/传感器/计数器；④ 只能人工 → 扫码/手持终端录入。
- 统一思路：**边缘采集网关做协议适配，向上统一成标准数据模型**（MQTT/OPC UA/HTTP），MES 只对接标准接口。

**加分点：** 体现"**协议适配层**"思维——不要让 MES 直接面对几十种设备协议，否则每接一台设备就改一次 MES。工业项目里这个架构决定后期维护成本。

## 第十部分：WPF 深化（105–119）

### 105. Visual Tree 与 Logical Tree 的区别？

**标准答法：**
- **Logical Tree（逻辑树）**：XAML 里你写的元素层级（如 Window → Grid → Button），反映**逻辑结构**。
- **Visual Tree（视觉树）**：实际渲染的完整元素树，包含控件模板展开的内部元素（如 Button 内部的 Border、ContentPresenter）。
- 用途：逻辑树用于数据绑定/资源查找；视觉树用于样式/模板/命中测试/遍历查找实际渲染元素。

**加分点：** 找元素用 `VisualTreeHelper`（遍历视觉树）或 `LogicalTreeHelper`。经典坑：`FindName` 找不到模板内的元素，因为它在视觉树而非逻辑树——需用 `template.FindName` 或 `VisualTreeHelper`。

### 106. WPF 的布局流程（Measure/Arrange）？

**标准答法：**
- 两阶段布局：
  1. **Measure（测量）**：父元素给子元素可用尺寸约束，子元素返回**期望尺寸**（`DesiredSize`）。
  2. **Arrange（排列）**：父元素按测量结果分配最终位置与尺寸（`RenderSize`）。
- 触发：属性变化/窗口尺寸变化会触发 `InvalidateMeasure`/`InvalidateArrange`，下一帧重排。

**加分点：** 性能要点：布局是**递归且昂贵**的操作，避免频繁触发（如动画改 `Width` 会反复布局，改用 `RenderTransform` 走渲染层不触发布局）。`MeasureOverride`/`ArrangeOverride` 是自定义面板的入口。

---

### 107. 自定义控件（CustomControl）与用户控件（UserControl）的区别？

**标准答法：**
- **UserControl**：把一组现有控件组合成一个"复合控件"，自带 XAML + Code-Behind，简单直接，样式定制能力弱。
- **CustomControl**：继承 `Control`，用 `ControlTemplate` 定义外观，支持换肤/样式/触发器，可复用性强，但实现复杂（需定义依赖属性、模板部件 `TemplatePart`）。
- 选择：项目内快速组合用 UserControl；需要主题化/对外发布的控件库用 CustomControl。

**加分点：** CustomControl 要用 `TemplatePart`（`[TemplatePart]` 特性）约定模板内必需元素，并在 `OnApplyTemplate` 中获取引用；缺了模板部件要有降级处理。

---

### 108. IValueConverter 与 IMultiValueConverter 怎么用？

**标准答法：**
- `IValueConverter`：`Convert`（源→目标）、`ConvertBack`（目标→源），用于绑定时做值转换（如 bool → Visibility、状态码 → 文字/颜色）。
- `IMultiValueConverter`：多值绑定（`MultiBinding`）时把多个源组合成一个值（如"姓 + 名"合成全名，或"数量 + 单价"算金额）。
- 使用：在资源中定义转换器实例，绑定里写 `Converter={StaticResource Xxx}`。

**加分点：** 性能提示：转换器是**每次绑定时调用**的，逻辑要轻；能用简单绑定（如 `StringFormat`、`DataTrigger`）就不要上转换器。MES 里"设备状态 → 颜色"用转换器或 DataTrigger 都可以，DataTrigger 更声明式。

---

### 109. DataTemplateSelector 与 Behavior 是什么？

**标准答法：**
- **DataTemplateSelector**：根据数据对象的类型/属性**动态选择 DataTemplate**（如不同设备类型显示不同卡片布局）。
- **Behavior（附加行为）**：用附加属性给控件"附加"可复用交互逻辑（如拖动、双击、滚动加载），无需改控件代码，是 MVVM 中"事件 → ViewModel"的常用手段。

**加分点：** Behavior 的典型用途：把 `MouseDoubleClick` 转成命令调用（`EventToCommand`），避免在 Code-Behind 写事件处理器——这是"MVVM 纯净化"的关键技巧。

### 110. 常用 MVVM 框架有哪些？CommunityToolkit.Mvvm 怎么用？

**标准答法：**
- 框架：**CommunityToolkit.Mvvm**（微软官方，轻量，源生成器）、**Prism**（模块化、区域导航、事件聚合）、**Caliburn.Micro**（约定优于配置）、**MVVM Light**（已停更）。
- CommunityToolkit 核心：`ObservableObject`（自动生成 `PropertyChanged`）、`[ObservableProperty]`（字段自动生成属性）、`[RelayCommand]`（自动生成命令）、`WeakReferenceMessenger`（消息）。

**加分点：** `[ObservableProperty]` + `[RelayCommand]` 是**源生成器**实现（编译期生成代码，零反射开销），比手写 INotifyPropertyChanged 和 RelayCommand 简洁得多。面试答"我用的 CommunityToolkit"，要能说出它解决了什么痛点。

### 111. ViewModel 之间如何通信？

**标准答法：**
- 方式：① **事件聚合器/Messenger**（松耦合，发布-订阅）；② 共享服务（通过 DI 注入同一服务）；③ 父 ViewModel 直接持有子 ViewModel 引用；④ 中介者模式。
- 推荐：**Messenger/EventAggregator**，解耦且支持弱引用（避免内存泄漏）。

**加分点：** 弱引用消息（`WeakReferenceMessenger`）的意义：订阅者被回收后消息不会强引用它，避免 ViewModel 泄漏。Prism 用 `IEventAggregator`，CommunityToolkit 用 `WeakReferenceMessenger`，讲清对应关系是加分点。

### 112. WPF 渲染与硬件加速？

**标准答法：**
- WPF 用 **DirectX** 渲染，默认硬件加速（GPU）；渲染管线：Visual → 渲染线程 → DirectX → 屏幕。
- 关闭硬件加速：`RenderOptions.ProcessRenderMode = RenderMode.SoftwareOnly`（驱动不兼容时兜底）。
- 渲染分层：`RenderOptions.SetBitmapScalingMode`、`EdgeMode` 等可控制质量。

**加分点：** 常见考点：**为什么动画用 `RenderTransform` 而不是改 `Width/Height`**——前者走合成/渲染层不触发重排，后者触发 Measure/Arrange，性能差数量级。这是 WPF 性能优化的第一原则。

### 113. WPF 性能优化的具体手段？

**标准答法：**
- **绑定**：少用双向绑定、用 `OneTime`（不需更新时）、减少绑定层级、避免绑定转换器做重活。
- **资源**：`Freeze()` 冻结 Brush/Pen/Geometry（可冻结对象），减少开销；共享资源。
- **布局**：避免深层嵌套、避免频繁触发 Measure、用 `Grid` 代替多层 `StackPanel`。
- **列表**：开启虚拟化 + `Recycling`。
- **渲染**：`RenderTransform` 代替布局属性、`BitmapCache` 缓存静态复杂内容、`SnapsToDevicePixels`。

**加分点：** 面试要能说出**优先级**：先查是不是绑定/布局问题（用 WPF Performance Suite / Visual Profiler），再谈冻结、缓存。别一上来就说"用缓存"，那不叫分析。

### 114. WPF 内存泄漏的常见原因？

**标准答法：**
1. **事件订阅未取消**：长生命周期对象（单例/静态）订阅短生命周期对象的事件 → 短对象被强引用无法回收。
2. **静态集合/字段持有引用**。
3. **DispatcherTimer 未停止**、**绑定未清理**。
4. **WPF 绑定到不可通知对象**（用 `WeakEventManager` 或弱引用）。
5. **自定义控件未释放资源**（如注册的全局钩子）。

**加分点：** 排查工具：`.NET Memory Profiler`、`dotMemory`、`ANTS`，看对象存活与引用链。修复：`WeakEventManager`、`WeakReferenceMessenger`、`Unloaded` 时退订。MES 长期运行的看板最容易被此类泄漏拖垮。

### 115. WPF 打印与导出报表怎么做？

**标准答法：**
- 打印：`PrintDialog` + `PrintVisual`（打印可视元素）、`XpsDocument`、或第三方报表（FastReport/Stimulsoft/DevExpress）。
- 导出：Excel（NPOI/ClosedXML/EPPlus）、PDF（iTextSharp/QuestPDF）。
- 做法：把数据渲染成可打印的 Visual（或报表模板），再输出。

**加分点：** 关键细节：**分页**（`PrintVisual` 不自动分页，需手动切页或用 `DocumentPaginator`）、**打印预览**、**打印机 DPI 适配**。MES 中标签打印（条码/二维码）常用专用标签打印机 SDK/ZPL 指令。

### 116. WPF 多语言/国际化怎么做？

**标准答法：**
- 方案：资源字典（每种语言一个 `.xaml`/`.resx`）+ 运行时切换 `Application.Current.Resources.MergedDictionaries`；或 `ResX` + `CultureInfo`。
- 绑定方式：`{DynamicResource Key}`（可运行时刷新）或转换器读取资源。
- 注意：`DynamicResource` 才能在切换语言后自动更新，`StaticResource` 不会。

**加分点：** 字体问题：中文/英文/阿拉伯语字体差异、排版方向（RTL）要单独处理。数字/日期/货币格式用 `CultureInfo` 而非硬编码。

### 117. WPF 与 WinForms 如何互操作？

**标准答法：**
- WPF 宿主 WinForms：`WindowsFormsHost` 包裹 WinForms 控件（如某些图表/相机控件只有 WinForms 版）。
- WinForms 宿主 WPF：`ElementHost` 包裹 WPF 控件。
- 注意：**空气效应（airspace）**——WPF 与 WinForms 控件不能真正重叠/透明叠加，WinForms 控件总在最上层。

**加分点：** 实际项目里常因"某个第三方控件只有 WinForms 版"而混用，但要知道 airspace 限制（弹窗/遮罩层会被覆盖），解决方案是避免重叠或用窗口级弹层。

### 118. WPF 的弹窗、托盘、全局快捷键怎么做？

**标准答法：**
- 弹窗：`Window.ShowDialog()`（模态）或自定义 `Popup`/`Adorner`；MVVM 下用 DialogService 抽象。
- 托盘：`NotifyIcon`（WinForms 组件）或第三方库，配合 `ContextMenu`。
- 全局快捷键：`RegisterHotKey`（Win32 API）或 `KeyBinding`（仅应用内有效）。

**加分点：** 区分**应用内快捷键**（`InputBindings`/`KeyBinding`，WPF 原生）与**系统级全局热键**（必须调 Win32 `RegisterHotKey`，且在窗口销毁时 `UnregisterHotKey`，否则热键残留）。

### 119. WPF 应用如何做单元测试与 UI 自动化？

**标准答法：**
- **单元测试**：测 ViewModel（纯逻辑、无 UI 依赖），Mock 服务层；这是 MVVM 的核心收益。
- **UI 自动化**：`WinAppDriver`、`Appium`、`TestStack.White`、`FlaUI`（推荐，基于 UIAutomation）。
- 分层：逻辑测 ViewModel，界面交互少量做 UI 自动化，避免大量脆弱 UI 测试。

**加分点：** 明确观点：**UI 测试成本高、易碎，占比应小**；重点覆盖 ViewModel 和核心业务逻辑。MES 客户端可对"报工流程"做几条端到端 UI 冒烟测试。

### 120. 和产品/业务方需求有冲突时怎么处理？

**标准答法：**

### 121. 生产事故怎么应急？

**标准答法：**
1. **止损优先**：先恢复服务（回滚/降级/切备用），不是先找根因。
2. **同步信息**：立刻通知相关方（含影响范围、预计恢复时间）。
3. **定位根因**：日志/监控/最近变更（80% 事故与变更相关）。
4. **复盘**：写事故报告（时间线、根因、影响、改进项、责任人），改进项要有 deadline。

**加分点：** "**先恢复、后分析**"是标准答案；反之"先查代码两小时"会被认为没有应急意识。工业场景还要考虑**数据一致性修复**（补录/对账）。

### 122. 你遇到过最大的技术挑战是什么？

**标准答法（用 STAR + 技术深度）：** 选一个**有难度、你主导解决、能讲清原理**的案例。示例：MES 采集端在设备高频上报下出现数据丢失与重复——通过引入 Redis Stream 缓冲 + 消费组 ACK + 幂等落库 + 断线补传解决，数据完整率从 92% 提升到 99.9%。

**加分点：** 结构：现象 → 分析（为什么丢/为什么重）→ 方案（对比过哪些）→ 结果（量化）→ 沉淀（形成了什么规范）。**不要选"加班赶需求"这种非技术挑战**。

### 123. 你如何做代码审查（Code Review）？

**标准答法：**
- 关注点：正确性（边界、异常、并发）、可维护性（命名、职责、重复代码）、性能（N+1、循环内 IO）、安全（SQL 注入、越权、敏感信息）、测试覆盖。
- 方式：小 PR、聚焦改动、给建议而非命令、区分"必须改"与"建议"。
- 工具：Git PR + 自动化（编译、单测、静态分析/格式检查）。

**加分点：** 提"**自动化能查的不要靠人看**"——格式、静态检查交给 CI，人只看逻辑与设计。这是成熟团队的标志。

### 124. 需求频繁变更怎么应对？

**标准答法：**
- 变更走**流程**：评估影响（工作量、风险、关联模块）→ 优先级排序 → 排期 → 书面确认。
- 用**迭代/小步交付**降低变更成本；核心接口/数据结构设计留扩展点（开闭原则）。
- 对"伪变更"（没说清的需求）先澄清再做。

**加分点：** 关键洞察：**变更成本随阶段指数上升**（设计期改 1，上线后改 10）。所以推动"前期蓝图确认 + 原型评审"，而不是被动接受所有变更。

## 附录：高频一句话速记（合集）

- **值类型 vs 引用类型**：栈 vs 堆，值拷贝 vs 引用拷贝。
- **装箱**：值类型→object 堆分配，性能差；泛型避免装箱。
- **string 不可变**，拼接用 StringBuilder。
- **委托**：类型安全函数指针，可多播；**事件**=受保护的委托，外部只能订阅。
- **泛型**：类型安全 + 免装箱 + 复用。
- **IEnumerable** 内存执行，**IQueryable** 下推数据库。
- **async/await**：I/O 密集、不阻塞线程；**不是**多线程本身。
- **GC**：自动回收，非托管资源用 IDisposable + using。
- **依赖属性**：值在字典中，支持绑定/样式/动画/值继承。
- **路由事件**：冒泡/隧道/直接，`PreviewXxx` 隧道先于 `Xxx` 冒泡。
- **绑定 Mode**：OneWay/TwoWay/OneTime；`INotifyPropertyChanged` 让 UI 自动更新。
- **MVVM**：View/ViewModel/Model，解耦 + 可测试。
- **ICommand**：Execute/CanExecute，RelayCommand 封装委托。
- **ControlTemplate** 管外观，**DataTemplate** 管数据呈现。
- **StaticResource** 加载期解析，**DynamicResource** 运行时动态解析（换肤）。
- **Dispatcher**：跨线程更新 UI，Invoke 同步 / BeginInvoke 异步。
- **ObservableCollection**：增删自动刷新 UI（List 不行）。
- **UI 虚拟化**：只创建可见项，大列表必备。
- **MES 核心**：计划执行、过程管控、数据采集、追溯、防错、质量。
- **MES vs ERP**：ERP 计划层，MES 执行层；MES 承上启下。
- **追溯**：正向/反向，批次级/单件级，条码 + 全链路采集 + 关联表。
- **防错**：扫码/工艺/参数/物料防错，质量从检验变预防。
- **OEE** = 时间开动率 × 性能开动率 × 合格品率。
- **设备集成**：OPC UA（主流）、Modbus、MQTT；采状态/产量/参数/报警。
- **SPC**：控制图 + CPK，超限自动报警，主动预防。

- **struct vs class**：值语义/栈 vs 引用语义/堆；看"是否需要身份"。
- **record**：编译器生成 Equals/with/ToString，按内容相等。
- **可空引用类型**：编译期注解，不改运行时。
- **yield**：状态机 + 延迟执行，LINQ 惰性求值的基础。
- **Expression 树**：IQueryable 能翻译 SQL 的原因。
- **const vs readonly**：编译期内联替换 vs 运行期赋值一次。
- **中间件**：洋葱模型，顺序决定行为，异常处理放最外层。
- **DI 生命周期坑**：Singleton 捕获 Scoped；WPF 需手动 CreateScope。
- **JWT**：无状态，注销靠黑名单/版本号/RefreshToken。
- **SignalR**：实时推送，集群需 Redis backplane，高频要节流。
- **gRPC vs REST**：内部高频用 gRPC，对外用 REST。
- **Redis 锁**：SETNX + 过期 + 标识校验 + Lua 原子释放。
- **MQ 幂等**：唯一键 + 去重表 + 状态机；至少一次投递是常态。
- **MES 架构**：中小型单体 + 模块化更合适，采集服务可独立。
- **B+ 树索引**：最左前缀、覆盖索引、避免函数运算、EXPLAIN。
- **隔离级别**：MySQL 默认 RR，PG 默认 RC；MVCC 支撑快照读。
- **死锁**：统一加锁顺序、缩小事务、UPDATE 必须走索引。
- **雪花 ID**：时间戳 + 机器 ID + 序列号，需处理时钟回拨。
- **ISA-95**：0 设备、1 控制、2 SCADA、3 MES、4 ERP。
- **工单状态机**：只允许合法流转 + 幂等 + 留痕。
- **WIP**：在制品，利特尔法则，越少越好。
- **批次 vs SN**：批次级 vs 单件级；锂电是 SN + 物料批次双维度。
- **Andon**：异常呼叫 + 可视化 + 数据化（响应时长统计）。
- **MES/WMS**：领料/投料/入库/退料接口，核心是批次一致 + 对账。
- **采集架构**：设备 → 网关 → MQ → MES，断线补传 + 时间同步。
- **锂电关键点**：涂布面密度/张力、卷绕对齐度、注液量、化成曲线、分容分档。
- **Visual Tree vs Logical Tree**：渲染树 vs 逻辑树，模板内元素在视觉树。
- **Measure/Arrange**：两阶段布局，动画用 RenderTransform 避免重排。
- **CustomControl vs UserControl**：模板化可换肤 vs 简单组合。
- **Freeze**：冻结 Brush/Geometry 提升渲染性能。
- **WPF 泄漏**：事件订阅、静态引用、DispatcherTimer、绑定未清理。
- **MVVM 框架**：CommunityToolkit（源生成器）、Prism（模块化/事件聚合）。
- **Recap 原则**：先恢复后分析；变更成本随阶段指数上升；自动化能查的不靠人眼。
